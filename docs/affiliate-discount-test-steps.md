# Affiliate 专属链接与折扣码测试步骤

本文档用于验证本地环境 `localhost:3000` 的 Affiliate 专属链接、专属折扣码、购买归因和后台管理是否符合当前实现。

## 1. 测试目标

- 验证管理员审核通过后，系统会为推广者生成专属推广链接和专属折扣码
- 验证推广者可在 `/settings/affiliate` 查看并复制专属链接和折扣码
- 验证用户在购买页输入有效折扣码后可以成功应用优惠
- 验证仅有折扣码时，订单可以归因到对应推广者
- 验证同时存在 Affiliate Cookie 和折扣码时，Cookie 归因优先，折扣码仅用于优惠
- 验证管理员可以编辑折扣码，且系统会校验唯一性
- 验证同一用户对同一个 Affiliate 折扣码的重复使用限制

## 2. 前置条件

- 已启动本地环境，访问地址为 `http://localhost:3000`
- 已有管理员账号，可访问 `/admin/affiliate/*`
- 已有 1 个待审核的推广者申请账号，记为“推广者 A”
- 已有 3 个普通测试账号，分别记为：
  - “用户 B”：测试仅通过专属链接下单
  - “用户 C”：测试仅通过折扣码下单
  - “用户 D”：测试 Cookie 与折扣码同时存在
- 支付环境可用；如果当前是沙盒环境，确保支付网关使用测试卡或测试流程

## 3. 测试数据

以下数据可直接作为测试单示例，也可以在管理员审核通过后替换成系统实际生成的数据。

### 3.1 示例推广信息

- 推广者账号：`affiliate.qa.01@example.com`
- 示例 Affiliate Code：`qaaff-123456`
- 示例专属折扣码：`QAAFF1234`

### 3.2 示例专属链接

最小专属链接：

```text
http://localhost:3000/?aff=qaaff-123456
```

推荐带 UTM 的专属链接：

```text
http://localhost:3000/?aff=qaaff-123456&utm_source=youtube&utm_medium=affiliate&utm_campaign=2026_affiliate_test&utm_content=qa__affiliate__round1
```

### 3.3 实际值获取方式

如果要使用系统真实值，请按下面方式获取：

1. 管理员进入 `/admin/affiliate/applications`
2. 审核通过推广者申请
3. 打开 `/admin/affiliate/affiliates`
4. 记录该推广者的：
   - 推广码 `code`
   - 折扣码 `discountCode`
5. 推广者本人登录后进入 `/settings/affiliate`，再次核对页面展示的专属链接和折扣码

## 4. 完整测试步骤

## 4.1 用例一：审核通过后自动生成专属链接和折扣码

**目标**：验证推广者申请审核通过后，系统自动生成唯一推广码和默认唯一折扣码。

**操作步骤**

1. 使用管理员账号登录后台。
2. 打开 `http://localhost:3000/admin/affiliate/applications`。
3. 找到“推广者 A”的申请记录，点击通过。
4. 打开 `http://localhost:3000/admin/affiliate/affiliates`。
5. 搜索“推广者 A”并进入该记录。

**预期结果**

- 该推广者状态为可用状态。
- 列表或详情中可以看到专属推广码。
- 列表或详情中可以看到专属折扣码。
- 折扣码不为空，且与其他推广者不重复。

## 4.2 用例二：推广者中心展示专属链接和折扣码

**目标**：验证推广者本人可以在设置页看到并复制自己的推广信息。

**操作步骤**

1. 使用“推广者 A”登录前台。
2. 打开 `http://localhost:3000/settings/affiliate`。
3. 查看页面中的 Affiliate 链接区域。
4. 查看页面中的折扣码展示区域。
5. 点击“复制链接”。
6. 点击“复制折扣码”。

**预期结果**

- 页面展示专属链接，格式为 `http://localhost:3000/?aff=<affiliate_code>`。
- 页面展示专属折扣码。
- 点击复制后有成功提示。
- 链接中的 `aff` 参数值与后台中该推广者的 `code` 一致。
- 页面中的折扣码与后台中的 `discountCode` 一致。

## 4.3 用例三：仅通过专属链接下单

**目标**：验证用户通过专属链接访问后，系统可以记录归因。

**操作步骤**

1. 退出所有账号，清理浏览器 Cookie，或使用全新无痕窗口。
2. 使用“用户 B”打开推广者 A 的专属链接，例如：

```text
http://localhost:3000/?aff=qaaff-123456&utm_source=youtube&utm_medium=affiliate&utm_campaign=2026_affiliate_test&utm_content=qa__affiliate__round1
```

3. 确认页面正常打开。
4. 登录“用户 B”。
5. 进入 `http://localhost:3000/pricing`。
6. 选择任意可购买套餐，完成支付。
7. 支付完成后，回到后台查看：
   - `/admin/affiliate/commissions`
   - `/admin/affiliate/affiliates`

**预期结果**

- 用户 B 可以正常下单。
- 订单应带有 Affiliate 归因信息。
- 对应推广者能看到新增的推广效果数据或佣金数据。
- 该场景即使没有输入折扣码，也应保留链接带来的归因。

## 4.4 用例四：仅通过折扣码下单

**目标**：验证没有 Affiliate Cookie 时，输入有效折扣码也可以完成优惠和归因。

**操作步骤**

1. 退出所有账号，清理浏览器 Cookie，或使用全新无痕窗口。
2. 使用“用户 C”直接打开 `http://localhost:3000/pricing`，不要先访问专属链接。
3. 选择一个套餐，打开支付弹窗。
4. 在折扣码输入框中输入专属折扣码，例如：

```text
QAAFF1234
```

5. 点击“应用”。
6. 确认页面显示折扣已生效。
7. 完成支付。
8. 支付完成后，回到后台查看推广者 A 的佣金、订单归因或推广数据。

**预期结果**

- 折扣码可以校验通过。
- 前端提示“折扣码已应用，结账时会自动带入”。
- 订单金额按折扣比例正确减少。
- 在没有有效 Affiliate Cookie 的前提下，该订单仍应归因到推广者 A。

## 4.5 用例五：同时存在专属链接 Cookie 和折扣码

**目标**：验证 Cookie 归因优先，折扣码仅用于优惠，不覆盖已有有效归因。

**操作步骤**

1. 退出所有账号，清理浏览器 Cookie，或使用全新无痕窗口。
2. 使用“用户 D”先访问推广者 A 的专属链接。
3. 保持当前浏览器会话不关闭，进入 `http://localhost:3000/pricing`。
4. 在支付弹窗中输入推广者 A 的专属折扣码。
5. 完成支付。
6. 支付后检查后台佣金归属和订单记录。

**预期结果**

- 折扣码可以正常应用。
- 订单价格按折扣码规则优惠。
- 订单归因优先使用已有的 Affiliate Cookie。
- 折扣码不会覆盖掉已存在的有效 Cookie 归因。

## 4.6 用例六：管理员编辑折扣码

**目标**：验证管理员可以修改折扣码，且系统会做唯一性校验。

**操作步骤**

1. 使用管理员账号打开 `http://localhost:3000/admin/affiliate/affiliates`。
2. 找到推广者 A。
3. 在折扣码编辑区域输入一个新的折扣码，例如：

```text
QAAFF2026
```

4. 点击“保存折扣码”。
5. 刷新页面并再次查看。
6. 再尝试把另一位推广者的折扣码修改成同样的 `QAAFF2026`。

**预期结果**

- 第一次保存成功后，页面刷新仍显示最新折扣码。
- 新折扣码可以在购买页正常校验通过。
- 当另一个推广者尝试使用同一折扣码时，系统应报唯一性错误，不能保存。

## 4.7 用例七：同一用户重复使用同一个 Affiliate 折扣码

**目标**：验证同一用户完成一次已支付订单后，不能再次使用同一个 Affiliate 折扣码。

**操作步骤**

1. 使用“用户 C”完成一次带 `QAAFF1234` 的成功支付。
2. 支付完成后，不更换账号，再次进入 `http://localhost:3000/pricing`。
3. 重新选择套餐。
4. 再次输入同一个折扣码 `QAAFF1234`。
5. 点击“应用”。

**预期结果**

- 系统不应再次允许该用户使用同一个 Affiliate 折扣码。
- 前端应提示该折扣码当前用户已使用过。

## 5. 建议检查项

除页面操作外，建议同时检查以下内容：

- 订单表中是否写入 `discountCode` 和 `affiliateDiscountCode`
- 有 Cookie 时，订单是否写入 Affiliate 归因相关字段
- 无 Cookie 但有有效折扣码时，订单是否写入对应推广者归因
- 后台 `/admin/affiliate/commissions` 是否出现对应佣金记录
- 推广者 `/settings/affiliate` 中的统计数据是否随订单变化

## 6. 测试通过标准

满足以下条件即可判定本轮测试通过：

- 推广者审核通过后能自动获得唯一推广码和唯一折扣码
- 推广者中心能展示并复制专属链接和折扣码
- 折扣码在购买页可正常校验和应用
- 仅折扣码下单时可以完成归因
- 链接 Cookie 与折扣码同时存在时，Cookie 归因优先
- 折扣码编辑支持唯一性校验
- 同一用户不能重复使用同一个 Affiliate 折扣码完成二次优惠
