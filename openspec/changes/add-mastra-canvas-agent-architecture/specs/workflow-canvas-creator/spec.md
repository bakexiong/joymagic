## 修改需求

### 需求：Create Canvas 必须提供可扩展的 Agent 接口层

系统必须为画布暴露稳定的 Agent 接口层，使后续聊天、灵感检索、自动布局、节点创建和节点更新都能通过统一入口操作画布；当智能体进入正式实施阶段时，该入口必须升级为服务端 Mastra 架构，而不是长期维持前端页面内的本地伪编排。

#### 场景：Agent 读取当前画布

- **当** 聊天或自动化能力需要读取当前创作状态
- **那么** 系统必须提供读取整个画布图和读取部分节点的能力
- **并且** 读取结果必须包含节点、边和当前上下文信息

#### 场景：Agent 修改当前画布

- **当** Agent 需要创建节点、更新节点、自动布局或分组
- **那么** 系统必须通过统一的画布接口执行这些操作
- **并且** 这些操作的结果必须以正式节点、边或布局变化回写画布

#### 场景：用户通过 Agent 聊天发起生成

- **当** 用户在 Create Canvas 底部的 Agent 聊天输入区提交图片或视频创作需求
- **那么** 系统必须将该消息编排为工作流节点创建或更新、必要的参考连线，以及一次正式生成执行
- **并且** 生成结果仍必须回写为画布中的结果节点或更新当前工作流节点

#### 场景：用户基于 skill 触发自动搭图

- **当** 用户选择某个 skill 后发起创作需求
- **那么** 系统必须结合该 skill 对应的工作流骨架自动生成画布节点、引用边和布局
- **并且** 自动生成出的节点结构必须与该 skill 的场景目标保持一致

说明：该场景在第一期只要求保留接入点，具体业务 skill 可在后续单独补充。

#### 场景：用户上传图片并通过 `@` 引用

- **当** 用户上传一张图片并在聊天中通过 `@` 指定其作为参考
- **那么** 系统必须能够将该图片接入当前画布工作流
- **并且** 后续生成必须使用该参考图参与节点创建、引用连线或参数注入

#### 场景：Agent 接口保持与 UI 解耦

- **当** 系统定义 Agent 接口
- **那么** 该接口必须面向画布图模型和正式节点操作
- **并且** 不得要求 Agent 直接操作具体 React 组件实例或 DOM 节点

#### 场景：系统切换到正式智能体平台

- **当** 团队为 Create Canvas 引入正式的服务端智能体平台
- **那么** 前端 `canvas-agent-adapter` 必须退化为 API 适配层或轻量 fallback
- **并且** 主要的聊天理解、工具决策和多轮会话逻辑必须迁移到服务端运行时

#### 场景：画布项目恢复聊天历史

- **当** 用户重新打开某个 Canvas Project
- **那么** 系统必须能够恢复该项目关联的聊天历史
- **并且** 聊天历史必须与当前画布项目保持一一关联的读取边界
