## 修改需求

### 需求：Create Canvas 必须提供独立的工作流画布入口

系统必须为 `/{locale}/create/canvas` 提供独立的工作流画布入口，用于组织图片与视频生成工作流，并以 project 作为高级模式的根实体。

#### 场景：用户从高级模式进入 Canvas

- **当** 用户从首页或其他入口进入 Canvas 高级模式
- **那么** 系统必须先创建一个属于该用户的 Canvas project
- **并且** 用户后续的画布状态必须绑定到该 project
- **并且** 系统不得将高级模式仅实现为无持久化的临时页面状态

## 新增需求

### 需求：Create Canvas 必须以 Project 作为持久化根实体

系统必须为每个 Canvas 会话创建稳定的 project 根实体，用于承载画布标题、归属用户、入口上下文和最近编辑信息。

#### 场景：系统创建新 Canvas 项目

- **当** 用户首次进入 Canvas 高级模式
- **那么** 系统必须创建新的 Canvas project
- **并且** project 必须拥有稳定唯一标识
- **并且** project 必须与当前登录用户绑定

#### 场景：系统打开已有 Canvas 项目

- **当** 用户访问 `/{locale}/create/canvas/{projectId}`
- **那么** 系统必须根据 `projectId` 加载对应项目
- **并且** 必须校验该项目归属于当前用户
- **并且** 未授权用户不得读取或修改该项目

### 需求：Create Canvas 必须持久化并恢复画布图状态

系统必须保存并恢复当前 Canvas graph，而不是只保存页面级表单字段。

#### 场景：用户修改画布内容

- **当** 用户修改节点、边、视口或可持久化的画布元信息
- **那么** 系统必须将变更写入该 project 的当前 snapshot
- **并且** 节点与边的唯一标识必须在保存后保持稳定

#### 场景：用户重新打开项目

- **当** 用户重新进入已有 Canvas project
- **那么** 系统必须恢复上次保存的节点、连线、视口和画布元信息
- **并且** 页面不得退化为空白默认画布
- **并且** 无效的临时运行时状态不得参与恢复

### 需求：Create Canvas 必须区分可持久化状态和运行时状态

系统必须明确区分可持久化 graph state 与纯运行时 UI state，避免把临时交互状态错误写入项目快照。

#### 场景：系统保存项目快照

- **当** 系统执行 snapshot 保存
- **那么** 必须只保存 nodes、edges、viewport、selection、composer references 与画布元信息
- **并且** 不得保存临时菜单开关、上传中的 object URL、轮询队列或瞬时 hover 状态

### 需求：首页进入高级模式时必须创建带初始工作流的项目

系统必须支持从首页输入框进入 Canvas 高级模式，并将当前输入转化为新 project 的初始 graph。

#### 场景：用户从首页点击 Open in Canvas

- **当** 用户在首页已经输入 prompt、scene、model、params 或参考图
- **那么** 系统必须先创建 Canvas project
- **并且** 必须将这些输入注入到初始 workflow node
- **并且** 若存在参考图，系统必须创建对应输入节点或等价引用结构
- **并且** 创建完成后必须跳转到该 project 的编辑页

### 需求：Create Canvas 必须支持自动保存与关键动作即时保存

系统必须提供自动保存能力，并对关键结构性修改执行即时保存。

#### 场景：用户持续编辑画布

- **当** 用户连续拖拽节点、修改 prompt 或调整参数
- **那么** 系统必须在短时间防抖后自动保存 project snapshot
- **并且** 不得在每次细粒度输入时立刻发送保存请求

#### 场景：关键结构发生变化

- **当** 用户新增节点、删除节点、删除连线或生成成功插入结果节点
- **那么** 系统必须立即或优先保存更新后的 snapshot
- **并且** 用户刷新页面后不应丢失这些关键结构变化
