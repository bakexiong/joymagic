## 上下文

项目当前首页已经具备工作台化的雏形，例如 `landing-v2` 中引入了 `HomeComposerSection`、`AiToolsSection` 和侧栏布局，但整体仍保留较重的落地页痕迹：

- Header 仍承担部分导航职责
- Sidebar 更像补充导航，而不是主导航
- Composer 虽然功能完整，但视觉上仍像复杂表单容器
- 首页内容区模块顺序偏“堆区块”，不够像产品首页

本次设计以桌面端为范围，移动端暂不纳入详细重构。

## 目标 / 非目标

### 目标

- 让首页桌面端成为真正的产品入口页
- 让用户进入首页后立即看到“创作入口 + 工具导航 + 用户状态”
- 让 Header、Sidebar、Composer 的职责明确且互不争夺视觉焦点
- 让中部内容区围绕“发现工具、理解能力、建立信任、引导升级”组织

### 非目标

- 不在本轮重构移动端首页
- 不在本轮重做博客页、定价页或工具详情页
- 不直接修改 `/content` 下的 mdx 文件

## 布局决策

### 1. 顶部结构

桌面端顶部采用两层结构：

- 第一层：`Marketing Bar`
- 第二层：`Header`

#### Marketing Bar

用于承载运营和增长信息，如：

- 新模型上线
- 节日折扣
- Credits 奖励活动
- 关键新功能入口

#### Header

Header 不再承担主导航，结构固定为：

- 左侧：Logo / 品牌信息
- 右侧：充值入口、多语言切换、用户积分、头像菜单

### 2. 左侧 Sidebar

Sidebar 成为首页主导航和任务入口的统一容器，承接原 Header 中的一级导航能力。

建议分组：

- Create
- Image
- Video
- Effects
- Explore
- Pricing / Upgrade

Sidebar 需要同时满足：

- 快速导航
- 强化任务导向
- 显示 New / Beta / Pro 状态

### 3. 中央主工作区

首屏核心是 `Home Composer`，采用三层结构：

- 顶部控制层：场景、模型、快捷参数
- 中部输入层：Prompt 输入区
- 底部操作层：上传、参数摘要、生成按钮、credits 提示

这里的目标不是展示更多控件，而是形成明确的创作闭环。

### 4. 中部内容区

首屏之后的模块顺序建议为：

1. 热门工具
2. 免费工具
3. 模型与能力展示
4. 作品灵感流
5. 关键优势
6. FAQ
7. Upgrade / Pricing 入口
8. 合规说明

## 组件决策

### Header

- 保留固定定位
- 去除横向一级导航
- 加强右上充值与用户状态可见性

### Sidebar

- 成为首页主导航
- 强化 active 状态和分组标题
- 保持任务型信息架构

### Home Composer

- 输入框视觉上必须成为首页最强焦点
- 参数控件统一为一套胶囊语言
- 生成按钮必须是最强 CTA
- 高级参数默认收起

### Marketing Bar

- 作为单独组件存在，避免 Header 职责膨胀
- 高度短，文案简洁

## 样式决策

首页整体应遵循根目录 `DESIGN.md` 中的设计系统，尤其是：

- 深色工作台分层
- Header 玻璃态
- Sidebar 实面板
- Composer 大圆角深色容器
- 蓝色主交互按钮

建议首屏配色关系：

- 页面底：`#050505` / `#0B0D12`
- Header：半透明深色 + blur
- Sidebar：实色深面板
- Composer：`#1D1D1F` / `#272729`
- 主 CTA：`#0071E3`

## 风险与注意事项

- 现有 `landing-v2` 中部分模块之间存在耦合，重排时要避免破坏翻译与数据注入
- Header 导航迁移到 Sidebar 后，需要确认首页和其他页是否共享同一 Header 组件
- Composer 重构时要优先保留现有功能，不要因重设计导致生成能力回退
- 营销位新增后，需要统一 Header 高度变量，避免布局错位

## 验证方式

- 桌面端检查首屏是否形成清晰的视觉三角：Logo / Composer / 用户操作
- 桌面端检查 Sidebar 是否已能承接主导航
- 检查输入框是否具备清晰的默认、hover、focus、loading 状态
- 检查首页首屏以下的模块顺序是否符合工作台首页逻辑
