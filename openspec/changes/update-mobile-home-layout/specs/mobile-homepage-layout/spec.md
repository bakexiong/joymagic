## 新增需求

### 需求：首页必须提供移动端独立布局编排

系统必须为首页提供独立于桌面端的移动端布局。该布局仅在移动端视口生效，桌面端首页结构与行为必须保持现状。

#### 场景：用户通过移动端访问首页

- **当** 用户在移动端视口访问首页
- **那么** 页面顶部首先展示移动端工具栏
- **并且** 工具栏下方依次展示 Banner slides、`Create Image` / `Create Video` 双 CTA、模型案例展示区
- **并且** 在模型案例展示区之后继续展示原首页 SEO 模块
- **并且** 可以继续展示原首页 hero 的标题与描述文案
- **但是** 不重复展示原首页 hero 中的产品 tabs 和生成表单

#### 场景：用户通过桌面端访问首页

- **当** 用户在桌面端视口访问首页
- **那么** 系统继续展示当前桌面端首页布局
- **并且** 不因移动端改造改变桌面端模块顺序

### 需求：移动端顶部工具栏必须复用现有导航能力

系统必须在移动端首页顶部提供独立工具栏。左上角为汉堡菜单入口，右上角为语言切换、主题切换和登录入口。

#### 场景：用户打开汉堡菜单

- **当** 用户点击左上角汉堡菜单按钮
- **那么** 系统展开原有功能菜单
- **并且** 展开后的菜单项结构、交互模式和样式与当前移动端菜单保持一致

#### 场景：用户查看顶部操作区

- **当** 用户进入移动端首页
- **那么** 右上角可见语言切换按钮、主题切换按钮和登录入口
- **并且** 这些操作入口不依赖 SEO 模块区域才可访问

#### 场景：已登录用户切换到旧版本首页

- **当** 已登录用户打开头像下拉菜单
- **那么** 菜单中可见“切换到旧版本”入口
- **当** 用户点击“切换到旧版本”入口
- **那么** 系统跳转到预先定义的旧版首页入口
- **并且** 该入口位于头像下拉菜单中

### 需求：移动端首页必须保持现有 SEO 文案不变

系统在重排移动端首页时，必须保留原首页 hero 与其他 SEO 模块的文案内容、字段值和语义输出，不得为本次改造修改 SEO 文案。

#### 场景：移动端首页渲染 SEO 模块

- **当** 系统在模型案例展示区后渲染原首页 hero 的标题描述区以及 features、faq 等 SEO 模块
- **那么** 模块文案内容与改造前保持一致
- **并且** 允许调整容器布局、模块顺序和移动端样式
- **但是** 不允许修改 SEO 文案字段值
- **并且** 原首页 hero 中的产品 tabs 和生成表单不在新布局中重复出现

### 需求：footer 在移动端首页改造中必须保持不变

系统必须保留首页现有 footer 的结构、内容和交互，不得因为移动端首页改造而修改 footer。

#### 场景：用户滚动到页尾

- **当** 用户滚动至首页 footer 区域
- **那么** footer 的内容结构、语言切换逻辑和链接行为与改造前一致
