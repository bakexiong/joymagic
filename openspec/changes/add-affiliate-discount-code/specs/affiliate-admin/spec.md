## 修改需求

### 需求：数据库必须提供分销业务主数据模型

系统必须提供分销申请、推广者档案、点击归因、佣金结算、提现申请、全局配置，以及推广者专属折扣码的持久化表结构，并与现有 `user / order / subscription` 建立关联。

#### 场景：为推广者生成默认折扣码

- **当** 申请审核通过或管理员直接创建推广者
- **那么** 系统必须为该推广者生成一个默认唯一折扣码
- **并且** 默认折扣码必须与推广者档案绑定

#### 场景：管理员编辑推广者折扣码

- **当** 管理员在 admin affiliate 模块编辑推广者折扣码
- **那么** 系统必须校验折扣码唯一性
- **并且** 系统必须保存最新折扣码配置

#### 场景：管理员设置折扣码有效期

- **当** 管理员创建或编辑推广者折扣码
- **那么** 系统必须允许管理员设置折扣码有效期
- **并且** 未显式设置时系统必须默认将有效期设置为创建时间后 30 天

#### 场景：订单通过 affiliate 折扣码成交

- **当** 用户在购买页输入有效的 affiliate 折扣码并成功下单
- **那么** 系统必须将该折扣码写入订单或订阅
- **并且** 该折扣码不得单独触发推广归因或佣金结算

### 需求：Admin 必须提供内嵌式分销管理模块

系统必须在现有 `admin` 管理后台中提供分销管理模块，并包含数据概览、推广者管理、申请审核、佣金管理、提现管理、全局配置页面，以及折扣码管理能力。

#### 场景：管理员查看推广者折扣码

- **当** 管理员打开推广者管理页面
- **那么** 系统必须展示每个推广者当前的专属折扣码
- **并且** 系统必须允许管理员执行编辑或停用操作

### 需求：分销模块首版必须支持静态运营视图

在后端接口尚未接入时，系统必须使用静态 mock 数据提供稳定可浏览的运营后台页面；在真实接口接入后，折扣码字段和操作必须切换到真实数据源。

#### 场景：推广者管理页接入真实折扣码数据

- **当** 推广者管理页切换到真实接口
- **那么** 系统必须使用真实的折扣码字段渲染列表和编辑区域
- **并且** 折扣码操作不得依赖本地 mock 状态

### 需求：推广者必须支持链接与折扣码双入口推广

系统必须同时支持推广链接和推广者专属折扣码两种传播入口。

#### 场景：推广者查看自己的折扣码

- **当** 推广者访问 `/settings/affiliate`
- **那么** 系统必须展示其专属推广链接和专属折扣码
- **并且** 页面必须提供便捷复制能力

#### 场景：购买页输入折扣码

- **当** 终端用户在站内购买页输入折扣码并点击兑换
- **那么** 系统必须校验折扣码是否存在且可用
- **并且** 系统必须校验折扣码是否仍在有效期内
- **并且** 系统必须向用户展示折扣应用结果

#### 场景：链接 cookie 与折扣码同时存在

- **当** 用户已存在有效 affiliate cookie 且又输入 affiliate 折扣码
- **那么** 系统必须优先保留 cookie 归因
- **并且** 折扣码仍可用于折扣计算，但不得覆盖有效 cookie 归因

#### 场景：仅存在折扣码而无有效 cookie

- **当** 用户没有有效 affiliate cookie，但输入了有效 affiliate 折扣码
- **那么** 系统必须允许该折扣码仅用于折扣计算
- **并且** 系统不得因为该折扣码单独创建推广归因或佣金记录
