## 新增需求

### 需求：桌面端图片 Playground 必须使用独立创作台结构

系统必须为 `/text-to-image/*` 与 `/image-to-image/*` 页面提供独立的桌面端 Playground 结构，不再复用旧版 PC 落地页双栏表单布局。

#### 场景：访问任意桌面端 text-to-image 页面

- **当** 用户在桌面端访问任意 `/text-to-image/*` 页面
- **那么** 页面必须在 `CreateLayout` 中展示桌面端专用创作台表单
- **并且** 不得渲染旧版 PC 双栏 landing 表单结构

#### 场景：访问任意桌面端 image-to-image 页面

- **当** 用户在桌面端访问任意 `/image-to-image/*` 页面
- **那么** 页面必须在 `CreateLayout` 中展示桌面端专用创作台表单
- **并且** 不得渲染旧版 PC 双栏 landing 表单结构

### 需求：桌面端图片 Playground 必须使用统一字段架构

系统必须以统一的字段架构组织桌面端图片 Playground，使 prompt、参考图、输出参数、数量和 CTA 融入同一创作面板。

#### 场景：桌面端 text-to-image 表单渲染

- **当** 桌面端渲染 `text-to-image` 表单
- **那么** 系统必须在统一创作面板中展示 prompt、输出参数和生成动作
- **并且** 参数区域不得通过额外卡片嵌套旧表单主体

#### 场景：桌面端 image-to-image 表单渲染

- **当** 桌面端渲染 `image-to-image` 表单
- **那么** 系统必须在统一创作面板中展示参考图上传、编辑 prompt、输出参数和生成动作
- **并且** 参数区域不得通过额外卡片嵌套旧表单主体

### 需求：模型切换与页面内容必须保持既有语义

系统在重写桌面端图片 Playground 时，必须保持模型切换和页面 SEO 内容的既有语义。

#### 场景：切换模型

- **当** 用户在桌面端工作台中切换模型
- **那么** 系统必须跳转到该模型对应的页面路由

#### 场景：输出页面正文内容

- **当** 页面渲染 `CreateLayout` 下方内容
- **那么** Hero 标题与描述必须位于工作台下方输出
- **并且** 原有 Features、FAQ、CTA 等 SEO 模块必须继续按原顺序输出
