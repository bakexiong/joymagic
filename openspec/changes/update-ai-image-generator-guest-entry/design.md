## 上下文

当前 `/ai-image-generator` 使用通用生成器组件，内部只有 `文生图` / `图生图` 两个 tab 和固定 provider/model 选择，不和 header `图片AI` 菜单保持一致。新需求要求该页面成为从移动端首页进入的统一图片 AI 入口，并在未登录场景下支持按 header 菜单中的真实场景与模型进行导航。

同时，用户已明确本次不实现已登录态，但要求未登录态先封装成独立组件，便于后续增加登录状态组件。因此页面结构必须先拆分为“页面容器 + 登录态分支 + 未登录态组件”，而不是直接在页面中堆叠实现。

## 目标

- 让 `/ai-image-generator` 成为未登录用户的统一图片 AI 选择入口
- 场景与模型范围对齐 header `图片AI` 菜单，避免两套导航配置漂移
- 为后续登录态页面增加独立组件时保留清晰的替换边界

## 非目标

- 本次不实现已登录用户的最终页面体验
- 本次不重构各个目标场景页面自身的生成逻辑
- 本次不引入新的后台配置系统来管理场景与模型映射

## 方案

### 1. 页面容器与登录态分支

`/ai-image-generator` 页面改为轻量容器，只负责：

- 读取登录状态
- 根据登录状态决定渲染哪个子组件
- 暂时只接入未登录态组件

未登录态组件单独封装，后续已登录态可以新增为并列组件，由容器统一切换。

### 2. 视觉与交互方向

基于 `ui-ux-pro-max` 技能检索结果，本页采用 `Lead Magnet + Form` 的转化结构，但视觉上不做传统白底表单，而是收敛为更符合 AI 创作工具的移动端工作台形式：

- 主风格：深色工作台
- 强调色：金色 CTA 与选中态
- 质感：轻量玻璃感卡片，避免高模糊和低对比度
- 页面层次：标题区、控制卡片、动态表单区、辅助提示区

推荐配色：

- 主背景：`#1C1917`
- 深文字/深层背景：`#0C0A09`
- 次级中性色：`#44403C`
- CTA 强调：`#CA8A04`

视觉约束：

- 保持高级、克制、偏专业工具的观感，不做廉价霓虹或过快动效
- 所有交互反馈以边框、阴影、透明度变化为主，避免大幅缩放造成跳动
- 移动端优先，优先保证 `375px` 宽度下的完整可用性

### 3. 场景来源统一

场景与模型列表应来源于现有 header `图片AI` 菜单结构，而不是在新页面中再维护一套静态枚举。这样可以保证：

- 一级场景范围一致
- 二级模型列表一致
- 菜单文案、跳转目标、排序保持一致

对于带 `children` 的场景，入口页展示模型下拉；对于直接带 `url` 的场景，入口页在选择后直接导航。

### 4. 表单跟随策略

未登录态页面下半部分展示“当前选择所对应目标页面的核心表单能力”。为了避免在提案阶段锁死具体实现方式，规范只约束结果：

- 场景切换后，展示的表单字段必须与当前目标页面一致
- 带模型列表的场景，在模型未选定前展示默认模型或占位态；选定后与目标模型页面一致
- 无模型列表的场景，不在入口页停留，直接跳转

这样实施时可以选择复用已有表单组件、抽出共享表单片段，或通过新的适配层组装，但不会改变用户可见行为。

### 5. 页面布局约束

未登录态组件应使用以下布局顺序：

1. 标题区：展示页面标题、简短说明、当前场景标题
2. 控制卡片：包含场景下拉框和按需出现的模型下拉框
3. 表单工作区：展示与当前目标页面一致的核心表单
4. 辅助提示区：展示 prompt 灵感、跳转提示或选择说明

其中控制卡片必须作为视觉焦点，表单工作区需要随选择变化稳定切换，避免布局大幅跳变。

## 风险与权衡

- 如果直接复制 header 菜单数据到新页面，后续容易发生导航漂移；因此优先约束为同源映射
- 如果不先拆分未登录态组件，后续接入已登录态时会把页面容器与未登录 UI 耦合在一起，增加替换成本
- 由于本次不实现已登录态，需要明确其为占位分支，避免实施时误把未登录态作为唯一长期方案
- 如果过度使用玻璃拟态和重模糊效果，会拉低移动端性能并影响表单可读性，因此设计上只采用轻量玻璃感
