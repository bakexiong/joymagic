## 修改需求

### 需求：Create Canvas 智能体平台运行边界

Create Canvas 智能体平台必须支持将主站 Web 服务与 Mastra Agent 运行时拆分为同仓库下的两个独立部署服务。

#### 场景：主站通过内部服务调用 Agent 运行时

- **当** 主站收到一个合法的 Canvas Agent 消息请求
- **那么** 主站必须通过内部服务协议调用独立 Agent 服务执行 Mastra workflow
- **并且** 主站不得再依赖进程内直接加载 `src/mastra` 作为默认执行路径

#### 场景：Agent 服务独立承载运行时

- **当** Agent 服务启动
- **那么** 它必须独立承载 Mastra 的 agents、workflows、tools、memory 与 observability
- **并且** 不得要求与主站共享同一个 Node 进程

#### 场景：主站保持外部 API 稳定

- **当** 前端调用现有 Canvas Agent 外部接口
- **那么** 主站必须继续作为对外入口
- **并且** Agent 服务默认只暴露内部调用接口，而不是直接面向前端开放

### 需求：Canvas Agent 服务间信任边界

主站与 Agent 服务之间必须建立明确的服务间鉴权与错误边界。

#### 场景：内部调用鉴权

- **当** 主站请求 Agent 服务
- **那么** 请求必须携带服务间鉴权凭证或签名
- **并且** Agent 服务必须拒绝无效或缺失凭证的调用

#### 场景：上游错误映射

- **当** Agent 服务返回超时、鉴权失败或内部错误
- **那么** 主站必须将其映射为稳定的对外错误语义
- **并且** 保留本地 fallback 或回滚开关用于短期故障切换
