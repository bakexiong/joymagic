# 积分估算规范

## 新增需求

### 需求：统一前端积分计算接口

所有前端组件必须使用 `/api/ai/estimate-credits` 接口来计算所需积分，禁止使用硬编码常量或本地计算函数。

#### 场景：固定积分场景
- **当** 前端组件需要显示固定积分场景的所需积分（如 text-to-image）
- **那么** 前端组件必须调用 `/api/ai/estimate-credits` 接口，传递场景名称（apiKey）
- **并且** 前端组件必须使用返回的 `requiredCredits` 值显示给用户
- **并且** 前端组件禁止使用硬编码的常量值

#### 场景：动态积分场景
- **当** 前端组件需要根据参数计算所需积分（如视频时长、分辨率等）
- **那么** 前端组件必须调用 `/api/ai/estimate-credits` 接口，传递场景名称和参数
- **并且** 当用户修改影响积分的参数时，前端组件必须重新调用接口获取最新积分
- **并且** 前端组件必须使用防抖机制避免频繁调用
- **并且** 前端组件必须使用缓存机制避免重复计算相同参数

#### 场景：积分显示
- **当** 前端组件需要显示所需积分
- **那么** 前端组件必须调用 `/api/ai/estimate-credits` 接口获取
- **并且** 前端组件必须显示加载状态（如果正在计算）
- **并且** 前端组件必须显示错误状态（如果计算失败）
- **并且** 前端组件必须显示计算出的积分值（如果成功）

#### 场景：积分检查
- **当** 前端组件需要检查用户是否有足够积分
- **那么** 前端组件必须调用 `/api/ai/estimate-credits` 获取所需积分
- **并且** 前端组件必须比较所需积分与用户剩余积分
- **并且** 如果积分不足，前端组件必须提示用户充值
- **并且** 前端组件禁止阻止用户尝试生成（后端会最终验证）

#### 场景：积分计算成功
- **当** `/api/ai/estimate-credits` 接口调用成功
- **那么** 系统必须显示返回的积分值
- **并且** 系统必须更新组件中的积分显示
- **并且** 系统必须缓存计算结果（如果参数相同）

#### 场景：积分计算失败
- **当** `/api/ai/estimate-credits` 接口调用失败（网络错误、API 错误等）
- **那么** 系统必须显示友好的错误提示
- **并且** 系统禁止阻止用户继续操作
- **并且** 系统可以显示默认值或"计算中"状态
- **并且** 系统必须提供重试机制

#### 场景：用户未登录
- **当** 未登录用户访问需要积分计算的组件
- **那么** 系统可以显示默认积分值或提示登录
- **并且** 系统禁止调用 API（如果 API 需要认证）

#### 场景：参数变化
- **当** 用户修改影响积分的参数（如视频时长、分辨率等）
- **那么** 系统必须使用防抖机制，延迟调用 API
- **并且** 在等待期间系统必须显示加载状态或上次计算的积分值
- **并且** 防抖时间必须合理（建议 300-500ms）

#### 场景：相同参数重复计算
- **当** 用户多次触发相同参数的积分计算
- **那么** 系统必须使用缓存机制，直接返回缓存结果
- **并且** 系统禁止重复调用 API
- **并且** 缓存必须有过期时间（建议 5-10 分钟）

### 需求：积分计算 Hook

系统必须提供一个通用的 `useEstimateCredits` Hook，用于统一管理积分计算逻辑，并禁止前端组件使用硬编码积分常量或本地计算函数。

#### 场景：使用 Hook
- **当** 前端组件需要使用积分计算功能
- **那么** 前端组件必须使用 `useEstimateCredits` Hook
- **并且** 前端组件必须传递场景名称（apiKey）和参数（params）
- **并且** Hook 必须返回积分值、加载状态、错误信息

#### 场景：Hook 防抖
- **当** Hook 检测到参数频繁变化
- **那么** Hook 必须使用防抖机制，延迟调用 API
- **并且** 防抖时间必须可配置（默认 300-500ms）

#### 场景：Hook 缓存
- **当** Hook 接收到相同的参数组合
- **那么** Hook 必须返回缓存的结果
- **并且** Hook 禁止重复调用 API
- **并且** 缓存必须有过期时间

#### 场景：Hook 错误处理
- **当** Hook 调用 API 失败
- **那么** Hook 必须返回错误信息
- **并且** Hook 必须提供重试机制
- **并且** Hook 禁止抛出异常，必须优雅处理

#### 场景：移除硬编码常量
- **当** 前端组件中存在 `const REQUIRED_CREDITS = X;` 或类似硬编码积分常量
- **那么** 这些常量必须被移除
- **并且** 组件必须改为使用 `useEstimateCredits` Hook 获取积分

#### 场景：移除本地计算函数
- **当** 前端组件中存在 `getRequiredCredits()`、`calculateRequiredCredits()` 等本地积分计算函数
- **那么** 这些函数必须被移除
- **并且** 组件必须改为使用 `useEstimateCredits` Hook 获取积分
