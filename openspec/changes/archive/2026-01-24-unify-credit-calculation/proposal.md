# 变更：统一前端积分计算

## 为什么

当前项目中，前端组件使用多种方式计算所需积分：

1. **硬编码常量**：如 `const REQUIRED_CREDITS = 6;`、`const REQUIRED_CREDITS = 15;` 等
2. **本地计算函数**：如 `getRequiredCredits()`、`calculateRequiredCredits()` 等，这些函数包含复杂的业务逻辑
3. **分散的计算逻辑**：每个组件都有自己的积分计算方式，导致：
   - 维护困难：当积分规则变更时，需要修改多个文件
   - 不一致性：不同组件可能使用不同的计算逻辑
   - 错误风险：硬编码的值可能与后端实际计算不一致

后端已经提供了统一的积分计算接口 `/api/ai/estimate-credits`，该接口使用 `credit-config.ts` 和 `pricing-config.ts` 中的配置进行准确计算，支持固定积分和动态积分（基于参数）两种模式。

为了确保前后端积分计算一致，简化维护，需要统一所有前端组件使用 `/api/ai/estimate-credits` 接口来计算积分。

## 变更内容

- **统一积分计算接口**：所有前端组件必须使用 `/api/ai/estimate-credits` 来计算所需积分
- **移除硬编码常量**：删除所有 `REQUIRED_CREDITS` 等硬编码常量
- **移除本地计算函数**：删除所有 `getRequiredCredits()`、`calculateRequiredCredits()` 等本地计算函数
- **动态积分计算**：对于需要根据参数动态计算积分的场景（如视频时长、分辨率等），通过 API 传递参数获取准确积分
- **实时积分显示**：在用户修改参数时，实时调用 API 更新显示的积分值

**重大变更**：
- 前端组件不再使用硬编码的积分值
- 所有积分计算都需要调用后端 API
- 需要处理 API 调用的加载状态和错误情况

## 影响

- **受影响规范**：
  - 前端积分计算规范（需要新增或修改）
  - API 调用规范（需要更新）
  
- **受影响代码**：
  - `/src/shared/blocks/**` - 所有包含积分计算的前端组件
  - `/src/themes/default/blocks/**` - 所有包含积分计算的前端组件
  - `/src/app/api/ai/estimate-credits/route.ts` - 已存在，需要确保支持所有场景和参数

- **迁移范围**：
  - 约 20+ 个前端组件文件需要更新积分计算逻辑
  - 需要移除所有硬编码的积分常量和计算函数
  - 需要添加 API 调用逻辑和错误处理

## 验收标准

### 功能验收

1. **所有组件积分计算正常**
   - 所有组件能正确调用 `/api/ai/estimate-credits` 获取积分
   - 固定积分场景（如 text-to-image）能正确显示积分
   - 动态积分场景（如视频生成）能根据参数正确计算积分

2. **实时积分更新**
   - 当用户修改影响积分的参数时（如视频时长、分辨率等），积分值能实时更新
   - 积分更新有适当的加载状态提示

3. **错误处理完整**
   - API 调用失败时显示友好错误信息
   - 网络错误时能正确处理
   - 场景不存在时返回明确错误

4. **性能优化**
   - 避免频繁调用 API（使用防抖或节流）
   - 缓存积分计算结果（相同参数不重复调用）
   - API 调用不影响用户体验

### 边界条件验收

1. **参数处理**
   - 参数格式正确传递（支持驼峰和下划线命名）
   - 可选参数正确处理
   - 参数验证失败时返回错误

2. **异常情况**
   - 网络错误正确处理
   - API 返回错误时正确处理
   - 用户未登录时正确处理

3. **向后兼容**
   - 确保积分计算逻辑与后端一致
   - 确保显示的积分值与实际扣除的积分一致
