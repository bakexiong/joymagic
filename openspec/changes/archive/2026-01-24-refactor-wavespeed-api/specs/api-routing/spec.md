# API 路由规范

## 新增需求

### 需求：AI 生成 API 路由

系统必须提供统一的 AI 生成 API 路由，所有 AI 场景的生成请求都应通过 `/api/ai/[scene]/generate` 接口处理。

#### 场景：图像生成请求
- **当** 前端组件调用图像生成 API（如 image-to-image, image-upscaler 等）
- **那么** 请求必须发送到 `/api/ai/{scene}/generate`，其中 `{scene}` 是场景名称（如 `image-to-image`, `image-upscaler`）
- **并且** 请求参数必须符合该场景在 `pricing-config.ts` 中定义的 `requestParams` 配置

#### 场景：视频生成请求
- **当** 前端组件调用视频生成 API（如 text-to-video, image-to-video 等）
- **那么** 请求必须发送到 `/api/ai/{scene}/generate`，其中 `{scene}` 是场景名称（如 `text-to-video/ltx-2-fast`, `image-to-video/veo-3-1`）
- **并且** 请求参数必须符合该场景在 `pricing-config.ts` 中定义的 `requestParams` 配置

#### 场景：场景不存在
- **当** 请求的场景在 `pricing-config.ts` 中不存在
- **那么** 系统必须返回错误响应，提示不支持的场景
- **并且** 错误响应必须包含所有可用场景的列表

#### 场景：用户未认证
- **当** 未登录用户尝试调用生成接口
- **那么** 系统必须返回 `401` 或错误响应，提示 `"no auth, please sign in"`
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录

#### 场景：参数验证失败
- **当** 请求参数不符合场景的 `requestParams` 配置（缺少必需参数、类型错误等）
- **那么** 系统必须返回错误响应，明确说明哪个参数有问题
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录

#### 场景：积分不足
- **当** 用户积分不足以支付生成请求所需的积分
- **那么** 系统必须返回错误响应，提示积分不足
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录
- **并且** 如果支持免费生成，系统必须优先使用免费生成额度

#### 场景：Provider 配置缺失
- **当** 场景在 `pricing-config.ts` 中存在，但对应的 Provider 配置缺失或无效
- **那么** 系统必须返回错误响应，提示配置问题
- **并且** 系统禁止扣除任何积分

#### 场景：API Key 配置缺失
- **当** Provider 配置存在，但 API Key 未配置或无效
- **那么** 系统必须返回错误响应，提示 API Key 配置问题
- **并且** 系统禁止扣除任何积分

#### 场景：外部 API 调用失败
- **当** 调用外部 AI 服务 API 时发生网络错误或超时
- **那么** 系统必须返回错误响应
- **并且** 系统必须自动退还已扣除的积分
- **并且** 如果已创建任务记录，系统必须更新任务状态为失败

#### 场景：外部 API 返回错误状态
- **当** 外部 AI 服务返回非成功状态码（如 400, 500 等）
- **那么** 系统必须返回错误响应，包含外部 API 的错误信息
- **并且** 系统必须自动退还已扣除的积分
- **并且** 如果已创建任务记录，系统必须更新任务状态为失败

#### 场景：同步响应（直接返回结果）
- **当** 外部 API 直接返回生成结果（非异步任务）
- **那么** 系统必须直接返回结果给前端
- **并且** 系统必须更新任务状态为成功（如果创建了任务记录）
- **并且** 响应必须包含 `output` 或 `outputs` 字段

#### 场景：异步响应（返回任务 ID）
- **当** 外部 API 返回任务 ID，需要后续查询状态
- **那么** 系统必须返回 `requestId` 或 `taskId` 给前端
- **并且** 系统必须创建任务记录到 `ai_task` 表，状态为 `PENDING` 或 `PROCESSING`
- **并且** 系统必须保存任务元数据（场景、参数等）

#### 场景：请求体解析失败
- **当** 请求体不是有效的 JSON 格式
- **那么** 系统必须返回错误响应，提示 JSON 解析错误
- **并且** 系统禁止扣除任何积分

### 需求：AI 状态查询 API 路由

系统必须提供统一的 AI 任务状态查询 API 路由，所有场景的状态查询都应通过 `/api/ai/status` 接口处理。

#### 场景：查询任务状态
- **当** 前端组件需要查询任务状态
- **那么** 请求必须发送到 `/api/ai/status?taskId={taskId}&scenario={scenario}`
- **并且** `taskId` 参数必须是必需的任务标识符
- **并且** `scenario` 参数是可选的场景名称（用于自动推断 provider 和 endpoint 配置）

#### 场景：任务完成
- **当** 查询已完成的任务状态
- **那么** 响应必须包含 `status: "completed"` 或 `status: "success"`
- **并且** 响应必须包含 `output` 或 `outputs` 字段，包含生成结果的 URL
- **并且** 任务状态和结果必须自动更新到 `ai_task` 数据库表

#### 场景：任务失败
- **当** 查询失败的任务状态
- **那么** 响应必须包含 `status: "failed"` 或 `status: "error"`
- **并且** 响应必须包含 `error` 字段，包含错误信息
- **并且** 任务状态必须更新到 `ai_task` 数据库表
- **并且** 系统必须自动触发积分退还

#### 场景：任务处理中
- **当** 查询正在处理的任务状态
- **那么** 响应必须包含 `status: "processing"`, `status: "pending"` 或类似状态
- **并且** 任务状态必须更新到 `ai_task` 数据库表

#### 场景：taskId 参数缺失
- **当** 查询状态时未提供 `taskId` 或 `requestId` 参数
- **那么** 系统必须返回错误响应，提示 `"taskId or requestId is required"`
- **并且** 系统禁止查询任何外部 API

#### 场景：任务不存在
- **当** 查询的 `taskId` 在外部 API 中不存在
- **那么** 外部 API 可能返回 404 或其他错误
- **并且** 系统必须返回错误响应，提示任务不存在
- **并且** 如果任务记录存在于 `ai_task` 表，系统必须更新状态为失败

#### 场景：Provider 和 Scenario 自动推断失败
- **当** 查询状态时未提供 `provider` 和 `scenario` 参数，且自动推断失败
- **那么** 系统必须返回错误响应，提示需要提供 `provider` 和 `scenario` 参数
- **并且** 错误消息必须包含参数格式说明

#### 场景：状态查询配置缺失
- **当** Provider 和 Scenario 存在，但未配置 `statusQueryEndpoint`
- **那么** 系统必须返回错误响应，提示状态查询端点未配置

#### 场景：状态查询超时
- **当** 查询外部 API 状态时发生超时（超过配置的 timeout）
- **那么** 系统必须返回错误响应，提示请求超时
- **并且** 系统禁止更新任务状态

#### 场景：状态响应解析失败
- **当** 外部 API 返回的响应格式不符合预期或无法解析
- **那么** 系统必须返回错误响应，提示响应解析失败
- **并且** 系统应在响应中包含调试信息（如果配置了 `_debug` 模式）

#### 场景：状态未知
- **当** 无法从响应中提取有效的状态值
- **那么** 系统必须返回 `status: "unknown"`
- **并且** 响应必须包含 `_debug` 字段，包含原始响应和映射配置，以便调试

#### 场景：任务结果格式多样
- **当** 任务完成，但结果格式不同（单个 output vs outputs 数组）
- **那么** 系统必须统一处理，确保响应同时包含 `output` 和 `outputs` 字段
- **并且** `outputs` 必须为数组格式，`output` 必须为字符串（取第一个元素）

#### 场景：多次查询同一任务
- **当** 前端多次查询同一个任务的状态
- **那么** 每次查询都必须返回当前最新状态
- **并且** 系统禁止重复退还积分（如果任务已失败）
- **并且** 系统禁止重复更新任务状态（如果状态未变化）

### 需求：前端 API 调用统一性

所有前端组件必须使用统一的 API 路由格式调用 AI 生成和状态查询接口。

#### 场景：生成接口调用
- **当** 前端组件需要调用 AI 生成接口
- **那么** 前端组件必须使用格式：`/api/ai/{scene}/generate`
- **并且** `{scene}` 必须与 `pricing-config.ts` 中定义的场景名称完全匹配
- **并且** 请求体参数必须符合该场景的 `requestParams` 配置

#### 场景：状态查询调用
- **当** 前端组件需要查询任务状态
- **那么** 前端组件必须使用格式：`/api/ai/status?taskId={taskId}&scenario={scenario}`
- **并且** `taskId` 必须是必需参数
- **并且** `scenario` 是可选参数，但建议提供以便自动推断配置

#### 场景：错误处理
- **当** API 调用返回错误
- **那么** 前端组件必须正确处理错误响应
- **并且** 前端组件必须显示用户友好的错误消息
- **并且** 对于认证错误，前端组件必须提示用户登录

#### 场景：网络错误处理
- **当** API 调用发生网络错误（如超时、连接失败）
- **那么** 前端组件必须捕获错误并显示友好的错误消息
- **并且** 前端组件应提供重试机制（如果适用）
- **并且** 前端组件禁止显示技术性的错误堆栈给用户

#### 场景：积分不足提示
- **当** API 返回积分不足错误
- **那么** 前端组件必须显示积分不足的提示
- **并且** 前端组件应提供跳转到充值或购买积分的链接（如果适用）
- **并且** 前端组件应刷新用户信息以更新积分显示

#### 场景：任务轮询
- **当** 生成接口返回任务 ID，需要轮询状态
- **那么** 前端组件必须定期调用 `/api/ai/status` 查询状态
- **并且** 轮询间隔必须合理（如 2 秒）
- **并且** 前端组件必须有最大轮询次数限制（如 120 次，约 4 分钟）
- **并且** 当任务完成或失败时，前端组件必须停止轮询

#### 场景：场景名称大小写和格式
- **当** 前端组件调用生成接口时
- **那么** 场景名称必须与 `pricing-config.ts` 中定义的完全匹配（区分大小写）
- **并且** 系统必须支持嵌套场景名称（如 `text-to-video/ltx-2-fast`）
- **并且** 如果场景名称不匹配，系统必须返回错误并提示正确的场景名称

#### 场景：参数类型转换
- **当** 前端传递的参数类型与配置不匹配（如字符串数字 vs 数字）
- **那么** 后端必须根据 `requestParams` 配置进行类型转换
- **并且** 如果类型转换失败，系统必须返回错误提示

#### 场景：可选参数和默认值
- **当** 前端未提供可选参数
- **那么** 后端必须使用配置中定义的默认值
- **并且** 如果配置了默认值，系统必须使用默认值继续处理

#### 场景：并发请求处理
- **当** 用户同时发起多个生成请求
- **那么** 每个请求必须独立处理
- **并且** 每个请求必须独立扣除积分
- **并且** 每个请求必须创建独立的任务记录

#### 场景：请求取消
- **当** 前端取消正在进行的请求（如用户离开页面）
- **那么** 已扣除的积分禁止退还（除非任务失败）
- **并且** 如果任务已创建，系统必须继续处理直到完成或失败
