# 变更：重构 Wavespeed API 路由

## 为什么

当前项目中存在两套 API 路由系统：
1. **旧的 `/api/wavespeed` 路由** - 包含大量场景特定的路由（如 `/api/wavespeed/image-to-image`, `/api/wavespeed/image-upscaler` 等），每个场景都有独立的实现
2. **新的 `/api/ai/[scene]/generate` 路由** - 统一的生成接口，通过配置驱动，支持所有场景

这种重复的架构导致：
- 代码维护成本高：需要同时维护两套路由系统
- 前端调用不一致：部分组件使用旧路由，部分使用新路由
- 状态查询分散：状态查询路由分散在各个场景下（如 `/api/wavespeed/image-to-image/status`），而新的统一状态查询接口 `/api/ai/status` 已经存在

为了统一 API 架构，简化维护，需要将所有 `/api/wavespeed` 下的 API 迁移到新的统一路由系统。

## 变更内容

- **迁移生成接口**：将所有 `/api/wavespeed/*` 下的生成路由迁移到 `/api/ai/[scene]/generate`
- **迁移状态查询**：将所有 `/api/wavespeed/*/status` 路由迁移到 `/api/ai/status`
- **更新前端调用**：更新所有前端组件中的 API 调用路径
- **移除旧路由**：在迁移完成后删除 `/api/wavespeed` 目录下的旧路由文件
- **保持向后兼容**：在过渡期间，可以考虑添加重定向或兼容层（可选）

**重大变更**：
- 所有 `/api/wavespeed/*` 路径将被废弃
- 前端组件需要更新 API 调用路径

## 影响

- **受影响规范**：
  - API 路由规范（需要新增或修改）
  - 前端 API 调用规范（需要更新）
  
- **受影响代码**：
  - `/src/app/api/wavespeed/` - 所有路由文件将被移除或迁移
  - `/src/shared/blocks/**` - 所有使用 `/api/wavespeed` 的组件
  - `/src/themes/default/blocks/**` - 所有使用 `/api/wavespeed` 的组件
  - `/src/app/api/ai/[scene]/generate/route.ts` - 已存在，需要确保支持所有场景
  - `/src/app/api/ai/status/route.ts` - 已存在，需要确保支持所有场景的状态查询

- **迁移范围**：
  - 约 24 个前端组件文件需要更新 API 调用
  - 约 45 个 `/api/wavespeed` 路由文件需要迁移或删除
  - 需要确保所有场景在 `pricing-config.ts` 中都有正确配置

## 验收标准

### 功能验收

1. **所有生成接口正常工作**
   - 所有图像生成场景（text-to-image, image-to-image, image-upscaler 等）能正常生成
   - 所有视频生成场景（text-to-video, image-to-video 等）能正常生成
   - 同步响应（直接返回结果）和异步响应（返回任务 ID）都能正确处理

2. **所有状态查询正常工作**
   - 能正确查询任务状态（pending, processing, completed, failed）
   - 能正确提取和返回任务结果（output/outputs）
   - 能正确处理任务失败并自动退还积分

3. **错误处理完整**
   - 未认证用户访问返回正确错误
   - 参数验证失败返回明确错误信息
   - 场景不存在返回错误并列出可用场景
   - 积分不足返回错误且不扣除积分
   - 外部 API 调用失败时自动退还积分

4. **积分系统正常**
   - 积分正确扣除
   - 任务失败时积分自动退还
   - 免费生成额度正确使用（如果支持）
   - 并发请求时积分独立扣除

5. **任务管理正常**
   - 异步任务正确创建任务记录
   - 任务状态正确更新
   - 任务结果正确保存
   - 多次查询同一任务不重复更新

### 边界条件验收

1. **参数处理**
   - 场景名称大小写敏感性正确
   - 参数类型转换正确（字符串数字 → 数字）
   - 可选参数和默认值正确使用
   - 嵌套场景名称正确支持（如 `text-to-video/ltx-2-fast`）

2. **异常情况**
   - 网络错误正确处理
   - 超时情况正确处理
   - 响应解析失败正确处理
   - 状态未知时返回调试信息

3. **并发和性能**
   - 并发请求独立处理
   - API 响应时间在合理范围内
   - 状态查询不阻塞

### 前端集成验收

1. **所有组件功能正常**
   - 所有前端组件在迁移后功能正常
   - 错误消息用户友好
   - 任务轮询逻辑正确（正确停止）
   - 积分不足时正确提示

2. **用户体验**
   - 加载状态正确显示
   - 错误状态正确显示
   - 成功状态正确显示
   - 认证错误时引导用户登录
