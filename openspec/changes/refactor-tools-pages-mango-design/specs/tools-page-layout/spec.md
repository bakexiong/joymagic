## 新增需求

### 需求：`/tools/*` 页面必须符合 Mango Animate 设计语言

系统必须让 `/tools/*` 页面采用 `mangoanimate.com-DESIGN.md` 规定的视觉语言，包括主色、按钮、卡片、边框、阴影、文字层级和留白节奏，不得继续以黑色工作台风格作为默认工具页外观。

#### 场景：用户进入任意统一工具页

- **当** 用户访问任意由 `/tools/[...tool]` 渲染的工具页
- **那么** 页面必须展示符合 Mango Animate 规范的主视觉和内容容器
- **并且** 主按钮、卡片、表单和标签区域必须使用统一的 Mango 风格样式

#### 场景：用户进入专用工具页

- **当** 用户访问 `/tools/face-generator` 等专用工具页
- **那么** 页面也必须遵循与统一工具页一致的 Mango 设计语言
- **并且** 不得保留明显割裂的旧工作台视觉体系

### 需求：工具页必须采用统一且可复用的页面骨架

系统必须为 `/tools/*` 页面提供统一且可复用的页面骨架，用于承载标题说明、标签切换、内容区和表单区，而不是在不同工具页中重复散落实现。

#### 场景：渲染工具页桌面端布局

- **当** 用户在桌面端访问工具页
- **那么** 页面必须采用符合规范的双栏或等效 12 栏布局
- **并且** 内容区与表单区必须具备清晰层级和稳定间距

#### 场景：渲染工具页移动端布局

- **当** 用户在移动端访问工具页
- **那么** 页面必须根据断点将内容区和表单区重排为适合触达的结构
- **并且** 不得要求用户在失控的全屏固定高度布局中完成主要操作

### 需求：视觉重构不得改变现有工具行为

系统在重构 `/tools/*` 页面视觉和布局时，必须保持现有生成、权限校验、积分估算、模板库、作品和收藏集逻辑可用，不得因为重构呈现层而破坏工具行为。

#### 场景：用户提交生成任务

- **当** 用户在新工具页布局中提交生成请求
- **那么** 系统必须继续走现有生成链路、鉴权和积分校验
- **并且** 生成完成后的结果仍必须在页面中正确展示

#### 场景：用户切换标签页

- **当** 用户在作品、收藏集和模板库之间切换
- **那么** 系统必须继续正确加载对应数据
- **并且** 新布局不得破坏原有的刷新、懒加载或切换行为
