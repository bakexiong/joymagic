## 新增需求

### 需求：模型维度落地页路由

系统必须提供以模型为中心的落地页路由，用于展示单一模型的能力、场景和工作台入口。

#### 场景：访问模型页

- **当** 用户访问 `/model/[slug]`
- **那么** 系统应渲染对应模型的落地页模板
- **并且** 页面应展示该模型支持的场景、示例内容和 FAQ

### 需求：复用 creator 工作台

模型页必须复用 `/creator` 的工作台表单和右侧结果面板，避免出现独立维护的第二套生成面板。

#### 场景：查看模型页工作台

- **当** 用户进入任一模型落地页
- **那么** 页面中的生成工作台应使用与 `/creator` 相同的右侧媒体面板
- **并且** 页面应支持通过 scene/model 参数切换到该模型的具体场景

### 需求：按模型展开对应场景

模型页必须围绕单一模型展开其对应的文本生成、图像编辑或其他适配场景。

#### 场景：浏览模型适用场景

- **当** 用户浏览模型落地页
- **那么** 页面应展示该模型支持的场景卡片
- **并且** 每个场景卡片应提供进入对应 scene/model 工作台的入口

### 需求：覆盖全部已注册模型

模型页系统必须为当前已注册到 playground 配置注册表中的模型提供可访问的 `/model/[slug]` 落地页，而不是只支持少数手工示例模型。

#### 场景：访问已注册模型的模型页

- **当** 某个模型已存在于 playground 配置注册表中
- **那么** 系统应为该模型生成稳定的 `/model/[slug]` 路由
- **并且** 页面至少应展示该模型可用的场景、复用 creator 工作台入口与基础模型说明

#### 场景：模型存在手工定制页数据

- **当** 某个模型同时存在通用自动生成数据和手工定制数据
- **那么** 系统应优先使用手工定制数据
- **并且** 不得因为自动生成逻辑覆盖已有定制文案与定制场景编排

### 需求：模型页区块文案支持按模型独立控制

模型页中的区块级文案不应只依赖一套全局共享模板；系统必须支持按模型生成或覆写区块级 copy，包括区块标题、说明、按钮与 controls 标签。

#### 场景：渲染模型页区块文案

- **当** 用户访问某个 `/model/[slug]` 页面
- **那么** 页面中的 why/how/workflows/gallery/faq 区块标题与说明应与该模型绑定
- **并且** 按钮文案、样片标签和 controls 标签也应按模型生成或读取模型级覆写

#### 场景：模型页使用模型级叙事配置

- **当** 系统为自动模型页生成区块文案
- **那么** 文案生成必须读取模型级配置，而不是只复用一套统一句式并替换模型名
- **并且** 不同模型应能通过配置体现不同的定位、阶段、证明方式或 CTA 风格
