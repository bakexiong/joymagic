## 新增需求

### 需求：工作台 Uploads 必须持久化到数据库
系统必须在用户上传图片、视频、音频等媒体到工作台时，将上传记录保存到数据库，以便后续在 `Uploads` 视图中复用。

#### 场景：上传图片后写入媒体库
- **当** 登录用户通过工作台上传图片成功
- **那么** 系统必须将该图片的上传记录写入数据库
- **并且** 记录必须至少包含用户、媒体类型、文件名、URL、上传时间

#### 场景：上传视频或音频后写入媒体库
- **当** 登录用户通过工作台上传视频或音频成功
- **那么** 系统必须将对应记录写入数据库
- **并且** 记录必须保留其媒体类型

#### 场景：图片或视频命中 NSFW 时禁止入库
- **当** 登录用户上传图片或视频且内容审核结果判定为 NSFW
- **那么** 系统必须阻止该上传记录写入数据库
- **并且** 上传接口必须返回明确的违规拦截结果

### 需求：Uploads 视图必须支持真实查询与筛选
系统必须让工作台 `Uploads` 视图基于服务端查询展示用户上传资产，并支持多维度筛选。

#### 场景：按媒体类型筛选
- **当** 用户选择图片、视频、音频等媒体类型
- **那么** 系统必须仅显示匹配该类型的上传记录

#### 场景：按日期范围筛选
- **当** 用户应用上传日期范围
- **那么** 系统必须仅显示上传时间落在该范围内的记录

#### 场景：按 scene 筛选
- **当** 用户在 `Tool` 中选择某个 scene
- **那么** 系统必须仅显示属于该 scene 的上传记录

#### 场景：按模型筛选
- **当** 用户在 `Model` 中选择某个模型
- **那么** 系统必须仅显示属于该模型的上传记录

### 需求：Tool 与 Model 筛选必须来自左侧工作台配置
系统必须让 `Tool` 与 `Model` 筛选项使用左侧工作台实际可选的 scene 和模型配置，而不是从当前结果列表反推。

#### 场景：Tool 列表来自 scene
- **当** 用户打开上传筛选面板
- **那么** `Tool` 选项必须显示左侧工作台可用的 scene 列表

#### 场景：Model 列表来自当前 scene
- **当** 用户选择某个 scene
- **那么** `Model` 选项必须显示该 scene 下可用的模型列表

### 需求：Uploads 视图必须支持关键字搜索
系统必须允许用户通过关键字检索上传资产。

#### 场景：按文件名或关联元数据搜索
- **当** 用户输入关键字
- **那么** 系统必须匹配文件名、scene 名称、model 名称等可搜索字段
- **并且** 仅显示匹配结果
