## 修改需求

### 需求：系统必须在已有画布节点时区分继续编辑与新建节点

当当前 Canvas Project 中已经存在可继续创作的画布节点时，系统必须能够区分用户本轮消息是要继续编辑已有节点，还是新建一组新的画布节点，而不能默认总是新建。

#### 场景：已有节点且用户目标不明确

- **当** 当前项目中已经存在可继续创作的 workflow 节点
- **并且** 用户发送的新消息未明确说明是继续修改现有节点还是另起一个新方向
- **那么** Canvas Agent 必须先返回一次澄清
- **并且** 澄清结果必须明确提供“在原节点上新增”与“新建画布节点”这两类选项或等价语义

#### 场景：用户显式选择了节点

- **当** 用户在发送消息前已经在画布中显式选中了一个或多个节点
- **那么** Agent 必须把这些选中节点作为“继续编辑”候选上下文的一等输入
- **并且** 不得在未确认前直接忽略 selection 并默认新建

#### 场景：用户确认在原节点上新增

- **当** 用户明确选择在原节点上新增
- **那么** 后续 workflow 必须复用对应节点上下文
- **并且** 系统必须新增一个派生节点，而不是覆盖原节点
- **并且** 不得强制改走“新建一组节点”的默认路径

#### 场景：用户确认新建节点

- **当** 用户明确选择新建一组新的画布节点
- **那么** 后续 workflow 必须创建新的节点组
- **并且** 新组不得与之前已有节点错误复用同一分组标识或编辑目标

### 需求：系统必须统一 auto 与 ask 的节点创建和生成触发流程

系统必须统一 `auto` 与 `ask` 两种模式在短提示词、节点归属判定、节点创建以及 `/generate` 触发时机上的行为差异。

#### 场景：提示词过短

- **当** 用户输入的提示词不足以直接创建工作流
- **那么** 系统必须返回建议卡片
- **并且** 不得创建文本节点、workflow 节点或新分组
- **并且** 不得触发 `/generate`

#### 场景：auto 模式下已有节点且用户选择在原节点上新增

- **当** 当前模式为 `auto`
- **并且** 当前项目存在可继续创作的已生成节点
- **并且** 用户确认“在原节点上新增”
- **那么** 系统必须在原节点上下文中新增一个节点
- **并且** 节点创建完成后必须立刻调用 `/generate`

#### 场景：auto 模式下已有节点且用户选择新建节点

- **当** 当前模式为 `auto`
- **并且** 当前项目存在可继续创作的已生成节点
- **并且** 用户确认“新建节点”
- **那么** 系统必须创建新的节点组
- **并且** 组内必须新增文本节点和对应 workflow 节点
- **并且** 节点创建完成后必须立刻调用 `/generate`

#### 场景：ask 模式下已有节点且用户选择在原节点上新增

- **当** 当前模式为 `ask`
- **并且** 当前项目存在可继续创作的已生成节点
- **并且** 用户确认“在原节点上新增”
- **那么** 系统必须在原节点上下文中新增一个节点
- **并且** 在真正调用 `/generate` 之前必须先弹出对应场景参数卡
- **并且** 只有用户在场景参数卡上确认后系统才可以调用 `/generate`

#### 场景：ask 模式下已有节点且用户选择新建节点

- **当** 当前模式为 `ask`
- **并且** 当前项目存在可继续创作的已生成节点
- **并且** 用户确认“新建节点”
- **那么** 系统必须创建新的节点组
- **并且** 组内必须新增文本节点和对应 workflow 节点
- **并且** 在真正调用 `/generate` 之前必须先弹出对应场景参数卡
- **并且** 只有用户在场景参数卡上确认后系统才可以调用 `/generate`
