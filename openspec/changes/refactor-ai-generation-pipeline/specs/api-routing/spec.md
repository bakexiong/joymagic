## 修改需求
### 需求：AI 生成 API 路由

系统必须提供统一的 AI 生成 API 路由，所有 AI 场景的生成请求都应通过 `/api/ai/[scene]/generate` 接口处理。该路由必须作为轻量入口调用统一生成提交服务，禁止继续在路由文件中直接堆叠认证、计费、Provider 调用、任务持久化和终态副作用。

#### 场景：图像生成请求
- **当** 前端组件调用图像生成 API（如 image-to-image, image-upscaler 等）
- **那么** 请求必须发送到 `/api/ai/{scene}/generate`，其中 `{scene}` 是场景名称
- **并且** 请求参数必须由统一请求验证服务按场景 `requestParams` 处理

#### 场景：视频生成请求
- **当** 前端组件调用视频生成 API（如 text-to-video, image-to-video 等）
- **那么** 请求必须发送到 `/api/ai/{scene}/generate`，其中 `{scene}` 是场景名称
- **并且** 嵌套场景名和动态 endpoint 必须由统一场景配置服务解析

#### 场景：场景不存在
- **当** 请求的场景在配置中不存在
- **那么** 系统必须返回错误响应，提示不支持的场景
- **并且** 错误响应必须包含所有可用场景的列表

#### 场景：用户未认证
- **当** 未登录用户尝试调用生成接口
- **那么** 系统必须返回认证错误
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录

#### 场景：参数验证失败
- **当** 请求参数不符合场景配置
- **那么** 系统必须返回错误响应，明确说明哪个参数有问题
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录

#### 场景：积分不足
- **当** 用户积分不足以支付生成请求所需的积分
- **那么** 系统必须返回错误响应，提示积分不足
- **并且** 系统禁止扣除任何积分
- **并且** 系统禁止创建任何任务记录
- **并且** 如果支持免费生成，系统必须优先使用免费生成额度

#### 场景：Provider 配置缺失
- **当** 场景存在，但对应的 Provider 配置缺失或无效
- **那么** 系统必须返回错误响应，提示配置问题
- **并且** 系统禁止扣除任何积分

#### 场景：API Key 配置缺失
- **当** Provider 配置存在，但 API Key 未配置或无效
- **那么** 系统必须返回错误响应，提示 API Key 配置问题
- **并且** 系统禁止扣除任何积分

#### 场景：外部 API 调用失败
- **当** 调用外部 AI 服务 API 时发生网络错误或超时
- **那么** 系统必须返回错误响应
- **并且** 系统必须自动退还已扣除的积分
- **并且** 如果已创建任务记录，系统必须更新任务状态为失败

#### 场景：外部 API 返回错误状态
- **当** 外部 AI 服务返回非成功状态码
- **那么** 系统必须返回错误响应，包含外部 API 的错误信息
- **并且** 系统必须自动退还已扣除的积分
- **并且** 如果已创建任务记录，系统必须更新任务状态为失败

#### 场景：同步响应
- **当** 外部 API 直接返回生成结果
- **那么** 系统必须直接返回结果给前端
- **并且** 系统必须更新任务状态为成功（如果创建了任务记录）
- **并且** 响应必须包含 `output` 和 `outputs` 字段
- **并且** 结果持久化和 R2 镜像必须通过终态服务处理，禁止阻塞成功响应

#### 场景：异步响应
- **当** 外部 API 返回任务 ID，需要后续查询状态
- **那么** 系统必须返回 `requestId` 或 `taskId` 给前端
- **并且** 系统必须创建任务记录到 `ai_task` 表，状态为 `PENDING` 或 `PROCESSING`
- **并且** 系统必须保存任务元数据

#### 场景：请求体解析失败
- **当** 请求体不是有效的 JSON 格式
- **那么** 系统必须返回错误响应，提示 JSON 解析错误
- **并且** 系统禁止扣除任何积分

### 需求：AI 状态查询 API 路由

系统必须提供统一的 AI 任务状态查询 API 路由，所有场景的状态查询都应通过 `/api/ai/status` 接口处理。该路由必须调用统一状态服务，状态服务必须复用与 webhook 回调相同的状态映射、输出抽取和终态处理逻辑。

#### 场景：查询任务状态
- **当** 前端组件需要查询任务状态
- **那么** 请求必须发送到 `/api/ai/status?taskId={taskId}&scenario={scenario}`
- **并且** `taskId` 参数必须是必需的任务标识符
- **并且** `scenario` 参数是可选的场景名称

#### 场景：本地终态短路
- **当** `ai_task` 中已有成功或失败终态结果
- **那么** 系统必须优先从数据库构建响应
- **并且** 系统禁止重复调用外部 Provider 状态接口
- **并且** 系统禁止重复退款

#### 场景：任务完成
- **当** 查询已完成的任务状态
- **那么** 响应必须包含 `status: "completed"` 或 `status: "success"`
- **并且** 响应必须包含 `output` 和 `outputs` 字段
- **并且** 任务状态和结果必须自动更新到 `ai_task` 数据库表
- **并且** 结果持久化、workbench creation、AI Character 同步和 R2 镜像必须由统一终态服务处理

#### 场景：任务失败
- **当** 查询失败的任务状态
- **那么** 响应必须包含 `status: "failed"` 或 `status: "error"`
- **并且** 响应必须包含 `error` 字段
- **并且** 任务状态必须更新到 `ai_task` 数据库表
- **并且** 系统必须自动触发一次且仅一次积分退还

#### 场景：任务处理中
- **当** 查询正在处理的任务状态
- **那么** 响应必须包含 `status: "processing"`、`status: "pending"` 或类似状态
- **并且** 任务状态必须更新到 `ai_task` 数据库表

#### 场景：taskId 参数缺失
- **当** 查询状态时未提供 `taskId` 或 `requestId` 参数
- **那么** 系统必须返回错误响应，提示 `"taskId or requestId is required"`
- **并且** 系统禁止查询任何外部 API

#### 场景：任务不存在
- **当** 查询的 `taskId` 在外部 API 中不存在
- **那么** 系统必须返回错误响应，提示任务不存在
- **并且** 如果任务记录存在于 `ai_task` 表，系统必须更新状态为失败

#### 场景：Provider 和 Scenario 自动推断失败
- **当** 查询状态时未提供 `provider` 和 `scenario` 参数，且自动推断失败
- **那么** 系统必须返回错误响应，提示需要提供 `provider` 和 `scenario` 参数
- **并且** 错误消息必须包含参数格式说明

#### 场景：状态查询配置缺失
- **当** Provider 和 Scenario 存在，但未配置 `statusQueryEndpoint`
- **那么** 系统必须返回错误响应，提示状态查询端点未配置

#### 场景：状态查询超时
- **当** 查询外部 API 状态时发生超时
- **那么** 系统必须返回错误响应，提示请求超时
- **并且** 系统禁止更新任务状态

#### 场景：状态响应解析失败
- **当** 外部 API 返回的响应格式不符合预期或无法解析
- **那么** 系统必须返回错误响应，提示响应解析失败
- **并且** 系统应在响应中包含调试信息（如果配置了 `_debug` 模式）

#### 场景：状态未知
- **当** 无法从响应中提取有效的状态值
- **那么** 系统必须返回 `status: "unknown"`
- **并且** 响应必须包含 `_debug` 字段，包含原始响应和映射配置，以便调试

#### 场景：任务结果格式多样
- **当** 任务完成，但结果格式不同
- **那么** 系统必须统一处理，确保响应同时包含 `output` 和 `outputs` 字段
- **并且** `outputs` 必须为数组格式，`output` 必须为字符串

#### 场景：多次查询同一任务
- **当** 前端多次查询同一个任务的状态
- **那么** 每次查询都必须返回当前最新状态
- **并且** 系统禁止重复退还积分
- **并且** 系统禁止重复创建相同结果记录

## 新增需求
### 需求：AI 生成终态处理必须集中且幂等

系统必须提供统一的任务终态处理服务，用于处理生成成功、生成失败、NSFW 拦截、webhook 成功回调和同步生成结果。终态处理必须集中管理任务状态、积分退款、结果持久化和后台存储镜像。

#### 场景：成功终态处理
- **当** 生成任务进入成功终态
- **那么** 系统必须归一化 `output` 和 `outputs`
- **并且** 系统必须更新 `ai_task.taskResult`
- **并且** 系统必须写入 workbench creation（若不存在）
- **并且** 系统必须异步尝试将结果镜像到 R2

#### 场景：失败终态处理
- **当** 生成任务进入失败终态
- **那么** 系统必须保存错误信息
- **并且** 系统必须按任务当前状态和退款记录保证只退款一次

#### 场景：重复终态处理
- **当** 同一个任务重复触发成功或失败终态
- **那么** 系统必须返回已存在的终态结果
- **并且** 系统禁止重复扣费、重复退款或重复创建结果记录

#### 场景：R2 镜像失败
- **当** 生成结果上传到 R2 失败
- **那么** 系统必须记录错误日志
- **并且** 生成接口、状态接口和 webhook 响应禁止因此失败
