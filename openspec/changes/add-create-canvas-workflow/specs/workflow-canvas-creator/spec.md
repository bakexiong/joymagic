## 新增需求

### 需求：Create Canvas 必须提供独立的工作流画布入口

系统必须为 `/{locale}/create/canvas` 提供独立的工作流画布入口，用于组织图片与视频生成工作流，不得将该页面实现为传统固定分栏 workbench 的简单变体。

#### 场景：用户访问 Create Canvas 页面

- **当** 用户访问 `/{locale}/create/canvas`
- **那么** 页面必须进入独立的画布创作模式
- **并且** 主交互区域必须是工作流画布而非固定表单面板

#### 场景：系统接入现有生成能力

- **当** Create Canvas 页面初始化可用场景
- **那么** 系统必须复用现有图片与视频生成场景配置
- **并且** 不得为该页面单独定义绕开现有生成链路的新后端协议

### 需求：Create Canvas 必须采用分层编辑器架构

系统必须将 `/{locale}/create/canvas` 实现为分层编辑器，而不是把旧 workbench 表单直接拼接进新页面。该分层至少包括页面壳、画布引擎层、DOM 浮层、生成适配层与 Agent 适配层。

#### 场景：页面初始化画布编辑器

- **当** 用户进入 Create Canvas 页面
- **那么** 页面壳必须负责路由、权限与初始化数据
- **并且** 画布引擎层必须独立承担节点、连线、视口和拖拽交互
- **并且** DOM 浮层必须独立承担顶部栏、工具轨道、底部控件与悬浮 composer

#### 场景：后续接入聊天或自动化

- **当** 系统后续需要接入聊天 Agent 或自动化动作
- **那么** 这些能力必须通过独立的 Agent 适配层读写画布
- **并且** 不得直接耦合到具体的节点渲染组件内部

### 需求：Create Canvas 必须使用 React Flow / XYFlow 真实工作流画布实现

系统必须使用 React Flow / XYFlow 提供真实工作流画布能力，包括节点渲染、曲线连接、平移、缩放、拖拽、Handle 连接生命周期与自定义 Edge，不得仅通过普通 DOM 模拟静态节点布局，也不得回退到 LeaferJS 或纯手写 canvas 作为主画布承载层。

#### 场景：用户拖动画布空白区域

- **当** 用户在画布空白区域按下并拖动
- **那么** 视口必须发生平移
- **并且** 现有节点布局应保持相对位置不变

#### 场景：用户使用鼠标滚轮或触摸板双指滑动

- **当** 用户在画布区域使用滚轮或触摸板双指滑动
- **那么** 系统必须默认将该操作解释为画布平移
- **并且** 不得把默认滚轮行为实现为直接缩放

#### 场景：用户使用组合键滚轮缩放

- **当** 用户按住 `Ctrl` 或 `Cmd` 后在画布区域滚轮
- **那么** 系统必须围绕当前指针位置缩放视口
- **并且** 节点与连线必须同步缩放

#### 场景：用户使用触控板双指捏合

- **当** 用户在画布区域执行触控板双指捏合
- **那么** 系统必须执行画布缩放
- **并且** 缩放结果必须与组合键滚轮缩放保持一致的视口语义

#### 场景：用户双击画布

- **当** 用户在画布区域双击
- **那么** 系统不得把双击解释为缩放动作

#### 场景：用户拖动节点

- **当** 用户拖动任一可移动节点
- **那么** 节点位置必须更新
- **并且** 与该节点相关的连接线必须同步更新

#### 场景：系统选择主画布技术基座

- **当** 团队实现 `/{locale}/create/canvas` 的主画布
- **那么** 必须使用 React Flow / XYFlow 作为唯一主画布技术基座
- **并且** 不得将 LeaferJS 作为主渲染引擎替代 React Flow / XYFlow

### 需求：Create Canvas 必须定义标准图数据模型

系统必须为 Create Canvas 定义稳定的图数据模型，至少覆盖节点、边、布局坐标、选中态、视口状态和节点上下文，而不是把这些信息散落在多个 UI 组件内部。

#### 场景：系统保存画布状态

- **当** 用户修改节点位置、连线关系或选中状态
- **那么** 系统必须将这些状态写入统一的画布图模型
- **并且** 节点与边必须拥有稳定的唯一标识

#### 场景：系统读取当前创作上下文

- **当** composer、命令菜单或 Agent 需要读取当前画布上下文
- **那么** 系统必须能够从统一图模型中获取当前节点、相关引用节点与连线关系
- **并且** 不得依赖某个局部组件树中的隐式状态

#### 场景：图模型覆盖完整画布状态

- **当** 系统定义 Create Canvas 的核心状态
- **那么** 图模型必须至少包含画布标识、节点集合、边集合、视口状态、选中状态和画布元信息
- **并且** 节点与边的顺序或坐标变化必须能够在不重建整页组件的情况下被独立更新

### 需求：Create Canvas 必须定义稳定的节点契约

系统必须为每个画布节点定义稳定契约，以便节点渲染、命令系统、composer 和生成适配层共享同一套结构。

#### 场景：系统创建任意节点

- **当** 系统创建输入节点、工作流节点、结果节点、工具节点、命令节点或群组节点
- **那么** 节点都必须具有稳定的 `id`、`kind`、`subtype`、位置、尺寸和 `data` 载荷
- **并且** 节点契约必须允许表达标题、状态和父子关系

#### 场景：系统扩展新的节点子类型

- **当** 后续需要新增新的生成节点或工具节点子类型
- **那么** 系统必须能够在不破坏既有节点字段的前提下扩展 `subtype`
- **并且** 旧节点渲染与既有 edge 逻辑不得因此失效

### 需求：Create Canvas 必须定义稳定的 edge 契约

系统必须为 edge 定义稳定契约，使 edge 同时承担渲染、输入约束和语义推导职责。

#### 场景：系统创建一条新 edge

- **当** 系统创建任意 edge
- **那么** edge 必须至少包含稳定的 `id`、`source`、`target` 和语义类型
- **并且** edge 必须允许携带 handle 信息和附加语义数据

#### 场景：系统根据 edge 推导下游上下文

- **当** 下游节点需要根据入边推导引用资源或生成模式
- **那么** 系统必须能够基于 edge 语义区分引用关系、结果回流关系、控制关系和命令关系
- **并且** 不得仅凭节点视觉位置推导业务逻辑

### 需求：Create Canvas 必须定义稳定的视口与选中态契约

系统必须为视口和平面交互定义稳定契约，使缩放、平移、聚焦与节点选中可以在 React Flow 层和 DOM 浮层之间可靠同步。

#### 场景：系统同步当前视口

- **当** 用户缩放或平移画布
- **那么** 当前视口状态必须写回统一状态容器
- **并且** 贴近节点的 DOM 浮层必须能够据此重新定位

#### 场景：系统同步当前选中节点

- **当** 用户选中、取消选中或切换选中节点
- **那么** 系统必须更新统一的选中态
- **并且** 节点高亮、composer 定位、命令菜单和底部操作区必须共享同一选中来源

### 需求：Create Canvas 必须采用 TapNow 风格的暗色视觉体系

系统必须为 Create Canvas 提供接近参考图的暗色无限画布视觉语言，包括黑色点阵背景、轻量节点卡片、细连接线、悬浮控件与克制的高亮层级。

该视觉规范的主要来源必须是用户指定的参考页面：

- `https://app.tapnow.ai/canvas/a40d6f74-459a-43f6-8613-7c34b4ee73da`

#### 场景：用户首次进入页面

- **当** 页面完成首屏渲染
- **那么** 用户应看到深色无限画布背景与低对比点阵底纹
- **并且** 画布不应呈现传统后台工作台的强分栏结构

#### 场景：节点处于默认状态

- **当** 节点未被选中
- **那么** 节点必须显示为深色轻量卡片
- **并且** 连线必须保持较低视觉权重

#### 场景：节点处于选中状态

- **当** 用户选中某个节点
- **那么** 节点描边和相关链路必须被适度提亮
- **并且** 高亮强度不得破坏整体克制风格

#### 场景：页面呈现整体构图

- **当** Create Canvas 页面完成布局
- **那么** 页面必须呈现全屏无外框编辑器构图
- **并且** 左上角必须保留轻量品牌与画布标题区
- **并且** 右上角必须使用悬浮胶囊操作按钮承载积分、社区和分享能力
- **并且** 左侧必须存在悬浮工具轨道而非传统侧边栏
- **并且** 底部左侧必须存在紧凑导航和缩放控件

#### 场景：页面呈现悬浮 composer

- **当** 用户选中工作流节点或进入节点编辑状态
- **那么** composer 必须以独立大卡片形式悬浮在节点链路附近
- **并且** 不得退化为固定右侧表单栏
- **并且** composer 必须在视觉上显著大于普通节点卡片

### 需求：Create Canvas 必须以节点作为核心创作单元

系统必须将模板、参考输入、当前工作流、输出结果和快速工具统一表达为节点，而不是让用户主要依赖固定侧栏完成创作。

#### 场景：用户查看当前画布

- **当** 画布存在输入、工作流和结果
- **那么** 页面必须以节点方式呈现这些对象
- **并且** 节点之间必须可通过连接关系表达引用或生成链路

#### 场景：系统展示最新输出

- **当** 某次生成完成
- **那么** 新结果必须以新的输出节点插入画布
- **并且** 输出节点必须可作为后续工作流的输入来源

#### 场景：系统创建不同职责的节点

- **当** 系统在画布中创建节点
- **那么** 节点必须至少区分输入节点、工作流节点、结果节点、工具节点、命令节点和群组节点
- **并且** 不同节点类型必须拥有各自的最小数据载荷与可执行动作

### 需求：Create Canvas 必须提供工作流节点

系统必须提供工作流节点作为创作闭环的核心节点，用于承载当前 prompt、scene、model、高频参数和生成动作。

#### 场景：用户选中工作流节点

- **当** 用户选中某个工作流节点
- **那么** 系统必须将其识别为当前主编辑目标
- **并且** composer 必须围绕该节点展示主输入与生成操作

#### 场景：工作流节点接收引用输入

- **当** 工作流节点接入图片、视频、模板或历史结果等上游节点
- **那么** 节点数据必须能够表达这些引用输入
- **并且** 这些输入必须参与生成模式和参数推导

### 需求：Create Canvas 必须提供结果节点

系统必须将每次成功生成的图片或视频表达为结果节点，而不是只在临时面板中展示结果。

#### 场景：图片生成成功

- **当** 某次图片生成成功
- **那么** 系统必须创建图片结果节点
- **并且** 结果节点必须显示缩略图或主视觉预览

#### 场景：视频生成成功

- **当** 某次视频生成成功
- **那么** 系统必须创建视频结果节点
- **并且** 结果节点必须能够参与后续引用或继续创作

#### 场景：用户从结果节点继续创作

- **当** 用户基于某个结果节点发起下一步动作
- **那么** 结果节点必须能够通过 edge 或 command node 作为新的输入来源
- **并且** 不得要求用户先把结果转移到页面外的历史或侧栏

### 需求：Create Canvas 必须提供命令节点

系统必须提供命令节点作为“从当前节点继续创作”的中间操作单元。

#### 场景：系统创建命令节点

- **当** 用户从节点发起连接但未命中合法目标
- **那么** 系统必须能够创建命令节点
- **并且** 命令节点必须携带来源节点上下文

#### 场景：命令节点展示可用动作

- **当** 命令节点显示给用户
- **那么** 系统必须根据来源节点类型提供相应动作
- **并且** 不可用动作不得以可点击状态出现

### 需求：Create Canvas 必须提供输入节点

系统必须提供输入节点，用于承载模板、上传素材、历史资源和参考资源，使这些内容以正式节点参与工作流。

#### 场景：系统创建参考输入节点

- **当** 用户上传图片、选择历史资源或引用模板内容
- **那么** 系统必须创建对应的输入节点或更新既有输入节点
- **并且** 这些节点必须能够被连接到工作流节点

#### 场景：输入节点作为参考资源

- **当** 某个输入节点被连接到工作流节点
- **那么** 系统必须将其识别为参考输入
- **并且** 必须能区分图片参考、视频参考和模板控制输入

### 需求：Create Canvas 必须提供工具节点和群组节点

系统必须支持工具节点和群组节点，以表达场景切换、快速能力入口和局部创作区域。

#### 场景：系统创建工具节点

- **当** 用户需要快速切换到某个生成场景或模型预设
- **那么** 系统可以创建工具节点表达这类控制动作
- **并且** 工具节点必须通过 `control` edge 影响目标工作流节点

#### 场景：系统组织局部创作区域

- **当** 用户需要把一组节点组织成局部工作区
- **那么** 系统必须支持群组节点或等价分组容器
- **并且** 节点的拖拽、边界和选中关系必须与群组状态兼容

### 需求：Create Canvas 的 edge 必须具备语义

系统必须将 edge 视为带语义的输入关系，而不是纯视觉曲线。edge 至少应支持引用、派生、结果回流、控制和命令占位等语义。

#### 场景：用户将结果节点连接到工作流节点

- **当** 用户把某个结果节点连接到工作流节点
- **那么** 系统必须将该连线识别为引用或派生关系
- **并且** 下游节点必须能够据此推导参考输入上下文

#### 场景：用户切换连线关系

- **当** 连线发生新增、删除或重连
- **那么** 系统必须重新计算相关节点的输入上下文
- **并且** 对模型、生成模式或参考资源的推导必须同步更新

### 需求：Create Canvas 必须支持 reference edge

系统必须支持 `reference` edge，用于表达图片、视频或其他参考资源被注入工作流节点作为生成输入。

#### 场景：图片节点作为参考输入

- **当** 用户将图片输入节点或图片结果节点连接到工作流节点
- **那么** 系统必须创建 `reference` edge
- **并且** 下游工作流节点必须将其识别为图片参考输入

#### 场景：视频节点作为参考输入

- **当** 用户将视频输入节点或视频结果节点连接到工作流节点
- **那么** 系统必须创建 `reference` edge
- **并且** 下游工作流节点必须将其识别为视频参考输入

#### 场景：reference edge 被移除

- **当** 用户删除某条 `reference` edge
- **那么** 系统必须从下游节点上下文中移除该参考输入
- **并且** 必须重新计算相关生成模式和默认参数

### 需求：Create Canvas 必须支持 derivation edge

系统必须支持 `derivation` edge，用于表达“从某个节点继续生成或继续创作”的链路。

#### 场景：从结果节点派生新的工作流节点

- **当** 用户从某个结果节点继续创建新的工作流节点
- **那么** 系统必须创建 `derivation` edge
- **并且** 新节点必须保留来源链路信息

#### 场景：从工作流节点派生新的工作流节点

- **当** 用户从当前工作流节点继续派生下一步工作流
- **那么** 系统必须能够创建 `derivation` edge
- **并且** 必须保留上下游之间的创作继承关系

### 需求：Create Canvas 必须支持 result edge

系统必须支持 `result` edge，用于表达某个结果节点来自哪个工作流节点的执行输出。

#### 场景：工作流节点生成图片结果

- **当** 某个工作流节点成功生成图片
- **那么** 系统必须在工作流节点与图片结果节点之间建立 `result` edge
- **并且** 该 edge 必须用于表达执行来源关系

#### 场景：工作流节点生成视频结果

- **当** 某个工作流节点成功生成视频
- **那么** 系统必须在工作流节点与视频结果节点之间建立 `result` edge
- **并且** 该 edge 必须用于表达执行来源关系

#### 场景：系统追溯结果来源

- **当** 用户查看某个结果节点的来源关系
- **那么** 系统必须能够基于 `result` edge 找到对应工作流节点
- **并且** 该关系不得依赖临时界面状态

### 需求：Create Canvas 必须支持 control edge

系统必须支持 `control` edge，用于表达模板节点、工具节点或预设节点对目标工作流节点的控制性影响。

#### 场景：模板节点影响工作流节点

- **当** 用户将模板节点应用到某个工作流节点
- **那么** 系统可以创建 `control` edge
- **并且** 目标节点必须根据该 edge 接收模板参数回填

#### 场景：工具节点影响工作流节点

- **当** 用户通过工具节点切换生成场景、模型预设或局部控制参数
- **那么** 系统必须以 `control` edge 表达这类关系
- **并且** 目标节点必须据此更新控制类数据

#### 场景：control edge 失效

- **当** 控制节点被删除、断开或不再适用
- **那么** 系统必须同步移除或失效对应 `control` edge
- **并且** 目标节点不得继续保留已失效的控制来源

### 需求：Create Canvas 必须支持 command edge

系统必须支持 `command` edge，用于表达用户从某个节点拖出后进入命令节点或命令菜单的临时创作链路。

- **那么** 系统必须能够创建 `command` edge 或与之等价的命令链路记录
- **并且** 该链路必须携带来源节点信息

#### 场景：命令动作完成后

- **当** 用户从命令节点或命令菜单中选定下一步动作
- **那么** 系统必须将临时 `command` 链路转化为正式节点与正式语义 edge
- **并且** 不再保留无效的临时 command 状态

#### 场景：命令流程被取消

- **当** 用户关闭命令节点、取消命令菜单或退出当前连线动作
- **那么** 系统必须清理临时 `command` edge 或等价状态
- **并且** 不得污染正式图数据

### 需求：Create Canvas 必须使用贴近节点的悬浮 Composer

系统必须在用户选中可编辑节点时显示贴近该节点的悬浮 composer，用于编辑 prompt、切换模型和触发生成，而不是固定在页面右侧显示整套旧表单。

#### 场景：用户选中当前工作流节点

- **当** 用户选中当前工作流节点
- **那么** 页面必须在节点附近显示悬浮 composer
- **并且** composer 必须支持 prompt 编辑、模型切换和生成操作

#### 场景：用户切换选中节点

- **当** 用户切换到另一个可编辑节点
- **那么** 悬浮 composer 必须更新到新的目标节点上下文
- **并且** 不得继续停留在固定侧栏位置

#### 场景：composer 引用画布上下文

- **当** 用户在 composer 中通过选中节点或 `@` 引用节点补充上下文
- **那么** composer 必须展示这些上下文引用
- **并且** 提交生成时必须将这些上下文转换为工作流输入

#### 场景：composer 管理当前工作流节点

- **当** 当前选中的节点为工作流节点
- **那么** composer 必须允许编辑 prompt、scene、model 和高频参数
- **并且** 这些修改必须直接回写该工作流节点的数据载荷

#### 场景：composer 处理不同上下文模式

- **当** composer 处于单节点、节点集合或命令派生模式
- **那么** 系统必须能够区分不同上下文来源
- **并且** 对引用 chip、默认 prompt 和生成动作进行相应调整

### 需求：Create Canvas 必须定义 composer 上下文契约

系统必须为 composer 定义稳定的上下文契约，使其能够消费当前激活节点、引用节点和推导输入，而不直接绑定任意局部 UI 状态。

#### 场景：系统读取 composer 上下文

- **当** composer 打开或切换目标节点
- **那么** 系统必须能够读取当前激活节点标识、引用节点列表和推导输入摘要
- **并且** 该上下文必须可被生成适配层和 Agent 层复用

#### 场景：系统清空 composer 上下文

- **当** 用户移除引用节点、切换场景或关闭当前编辑状态
- **那么** 系统必须能够局部或整体清理 composer 上下文
- **并且** 清理行为不得误删画布正式节点数据

### 需求：Create Canvas 必须提供 command node / command menu 机制

系统必须允许用户从已有节点继续派生新的创作动作；当用户从节点发起连接但未命中合法目标时，系统必须提供 command node 或 command menu。

#### 场景：用户从节点拖出连接但未命中目标节点

- **并且** 用户必须可以直接选择下一步动作

#### 场景：用户选择某个命令创建下一步节点

- **当** 用户在 command node 或 command menu 中选择图生图、图生视频、上传素材或模板等动作
- **那么** 系统必须自动创建对应节点
- **并且** 必须自动建立与来源节点的语义 edge

#### 场景：命令菜单呈现样式

- **当** command node 或 command menu 显示
- **那么** 它必须采用深色悬浮卡片样式
- **并且** 每个命令项必须至少包含图标和主标签

### 需求：Create Canvas 必须复用现有图片视频生成链路

系统在 Create Canvas 中触发生成时，必须继续复用现有图片/视频生成接口、积分估算、访问校验、上传能力和模型配置体系。

#### 场景：用户在画布中发起图片生成

- **当** 用户通过 composer 提交图片生成
- **那么** 系统必须调用现有图片生成链路

#### 场景：用户在画布中发起视频生成

- **当** 用户通过 composer 提交视频生成
- **那么** 系统必须调用现有视频生成链路
- **并且** 返回结果后在画布中插入视频输出节点

#### 场景：涉及参考图上传

- **当** 当前场景需要参考图或参考媒体
- **那么** 系统必须复用现有上传能力
- **并且** 不得在前端暴露新的密钥或直连第三方上传逻辑

#### 场景：系统将节点语义转换为现有生成参数

- **当** 用户从工作流节点发起生成
- **那么** 系统必须通过专用适配层把节点、引用节点和高频参数转换为现有生成链路所需参数
- **并且** 不得要求后端新增专门针对 Canvas 的生成协议

#### 场景：系统根据输入引用推导生成模式

- **当** 某个工作流节点接入图片、视频或模板类引用节点
- **那么** 生成适配层必须根据引用类型推导可用生成模式和默认参数
- **并且** 不得把所有推导逻辑散落在节点组件内部

### 需求：Create Canvas 必须定义生成适配层契约

系统必须定义单独的生成适配层契约，用于把画布中的节点语义转换为现有生成链路可执行的请求。

#### 场景：系统从工作流节点构建生成请求

- **当** 用户在 workflow node 上点击生成
- **那么** 生成适配层必须能读取该节点及其上游引用关系并构建标准请求
- **并且** 必须继续复用现有场景配置、访问校验和积分估算机制

#### 场景：系统处理生成成功结果

- **当** 现有生成链路返回成功结果
- **那么** 生成适配层必须负责创建对应 result node
- **并且** 必须建立 result edge 以表达结果来源

### 需求：Create Canvas 必须支持模板与结果回流

系统必须允许用户将模板参数、历史结果或当前输出重新注入当前工作流节点，形成连续迭代的创作链路。

#### 场景：用户引用模板节点

- **当** 用户对模板节点执行应用操作
- **那么** 模板中的 prompt 与相关参数必须回填到当前工作流节点
- **并且** 用户应能够继续在 composer 中微调后再生成

#### 场景：用户引用历史输出节点

- **当** 用户选择某个历史输出节点作为下一轮输入
- **那么** 系统必须将该结果注入当前工作流上下文
- **并且** 对 image-to-image 或 image-to-video 场景应能作为参考媒体参与生成

#### 场景：用户从模板节点派生工作流节点

- **当** 用户在画布中使用模板节点或模板命令
- **那么** 系统必须创建或更新目标工作流节点
- **并且** 模板中的 prompt、scene、model 和高频参数必须可以被继续微调

### 需求：Create Canvas 必须提供可扩展的 Agent 接口层

系统必须为画布暴露稳定的 Agent 接口层，使后续聊天、灵感检索、自动布局、节点创建和节点更新都能通过统一入口操作画布。

#### 场景：Agent 读取当前画布

- **当** 聊天或自动化能力需要读取当前创作状态
- **那么** 系统必须提供读取整个画布图和读取部分节点的能力
- **并且** 读取结果必须包含节点、边和当前上下文信息

#### 场景：Agent 修改当前画布

- **当** Agent 需要创建节点、更新节点、自动布局或分组
- **那么** 系统必须通过统一的画布接口执行这些操作
- **并且** 这些操作的结果必须以正式节点、边或布局变化回写画布

#### 场景：用户通过 Agent 聊天发起生成

- **当** 用户在 Create Canvas 底部的 Agent 聊天输入区提交图片或视频创作需求

#### 场景：Agent 接口保持与 UI 解耦

- **当** 系统定义 Agent 接口
- **那么** 该接口必须面向画布图模型和正式节点操作

### 需求：Create Canvas 必须定义模板与历史适配层契约

系统必须为模板回填和历史结果回流定义独立适配层，而不是将模板和历史逻辑直接写入节点 UI 组件。

#### 场景：系统应用模板到工作流节点

- **当** 用户从模板节点、模板面板或命令菜单应用模板

#### 场景：系统将历史结果重新注入工作流

- **当** 用户把历史结果用作新的参考输入
- **那么** 历史适配层必须负责把历史资源转换为输入节点或引用关系
- **并且** 必须保持与当前工作流节点的数据契约一致

### 需求：Create Canvas 必须采用稳定的模块拆分

系统必须将画布能力拆分为稳定模块，而不是集中在单个超大组件中。模块边界至少应覆盖页面壳、核心状态、运行时层、节点层、命令层、composer 层、适配器层和 UI 外框层。

#### 场景：系统组织画布代码

- **当** 开发者实现 Create Canvas
- **那么** 代码必须拆分为独立模块目录
- **并且** 节点渲染、视口控制、命令系统和生成适配不得全部堆叠在同一个文件中

- **那么** 应能分别在节点模块和生成适配模块中完成变更
- **并且** 不得要求同时修改大量无关 UI 外框代码

#### 场景：系统按模块组织文件

- **当** 团队组织 Create Canvas 相关代码
- **那么** 至少应存在页面壳、核心状态、运行时、节点、命令、composer、适配器和 UI 外框等模块目录
- **并且** 首批组件实现顺序必须与这些模块边界保持一致

### 需求：Create Canvas 必须提供独立的页面壳模块

系统必须通过独立页面壳模块承载路由、初始化数据、权限门控和编辑器装配，而不是让画布运行时直接承担页面级职责。

- **当** 用户进入 `/{locale}/create/canvas`
- **那么** 页面壳模块必须负责创建编辑器根结构
- **并且** 画布运行时、浮层 UI 和适配器必须通过页面壳被统一装配

#### 场景：页面处理路由和国际化

- **当** 页面需要处理 locale、查询参数或页面级跳转
- **那么** 这些职责必须由页面壳模块承担

#### 场景：系统复用图状态给多个模块

#### 场景：系统渲染节点与边

#### 场景：系统新增节点类型

#### 场景：系统渲染全局导航与轨道

- **当** 页面需要展示顶部按钮、工具轨道和底部缩放控件
- **那么** 这些界面必须由独立 UI 外框模块承担
- **并且** 不得直接混入节点渲染模块或运行时层

#### 场景：UI 外框读取当前状态

- **当** 顶部栏、工具轨道或底部控件需要感知当前选中节点、缩放比例或画布状态
- **那么** 它们必须通过核心状态模块读取这些信息
- **并且** 不得各自维护重复状态

### 需求：Create Canvas 必须按最小闭环优先实施

系统的首批实现必须优先形成“工作流节点生成 -> 结果节点插入 -> 从结果继续创作”的闭环，再逐步补齐模板、历史、Agent 和高级节点。

#### 场景：首批上线范围

- **当** 团队实施首批 Create Canvas
- **那么** 必须至少包含 workflow node、result node、command node、真实画布视口和悬浮 composer
- **并且** 必须支持调用现有图片或视频生成链路
- **并且** 必须支持新结果作为下一轮输入继续创作

#### 场景：后续能力渐进扩展

- **当** 团队在首批闭环基础上继续扩展
- **那么** 模板回填、历史回流、Agent 自动布局和更多节点类型应作为后续增量能力加入
- **并且** 首批闭环的节点、edge 与 composer 契约必须保持稳定

### 需求：Create Canvas 必须提供桌面优先、移动降级的体验

系统必须优先保证桌面端拥有完整画布体验，并为较小屏幕提供可用的降级交互，而不是强行复刻桌面级自由编排。

#### 场景：用户在桌面端访问页面

- **当** 用户在桌面端设备访问 Create Canvas
- **那么** 页面必须提供完整画布、节点拖拽、缩放和平移能力

#### 场景：用户在移动端访问页面

- **当** 用户在较小屏幕访问 Create Canvas
- **那么** 系统必须提供可用的降级交互
- **并且** 不得因桌面级布局直接导致核心生成功能不可用
