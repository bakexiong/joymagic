## 需求
### 需求：层级计费计算器

系统必须支持 `tier-based` 计算器类型，能够根据实际参数值自动匹配到最近的层级，并按该层级的定价配置计算积分。

#### 场景：层级匹配 - 小于最小层级
- **当** 实际参数值小于配置的最小层级值
- **那么** 系统必须按最小层级计费
- **例如** 层级配置为 [5, 10, 15, 30]，实际值为 3，系统按层级 5 计费

#### 场景：层级匹配 - 在两个层级之间
- **当** 实际参数值在两个层级之间
- **那么** 系统必须向上取整到较大的层级
- **例如** 层级配置为 [5, 10, 15, 30]，实际值为 7，系统按层级 10 计费
- **例如** 层级配置为 [5, 10, 15, 30]，实际值为 12，系统按层级 15 计费

#### 场景：层级匹配 - 等于某个层级
- **当** 实际参数值等于某个层级值
- **那么** 系统必须按该层级计费
- **例如** 层级配置为 [5, 10, 15, 30]，实际值为 10，系统按层级 10 计费

#### 场景：层级匹配 - 大于最大层级
- **当** 实际参数值大于配置的最大层级值
- **那么** 系统必须按最大层级计费
- **例如** 层级配置为 [5, 10, 15, 30]，实际值为 35，系统按层级 30 计费

#### 场景：层级列表自动排序
- **当** 系统处理层级配置
- **那么** 系统必须自动将层级列表从小到大排序
- **并且** 系统必须忽略层级配置中的顺序
- **例如** 配置 [30, 5, 15, 10] 和 [5, 10, 15, 30] 效果相同

#### 场景：积分计算
- **当** 系统确定了匹配的层级
- **那么** 系统必须从 provider 的 `tierPricing` 配置中获取该层级的定价信息
- **并且** 系统必须使用该层级的 `costPrice` 和 `profitMargin` 计算积分
- **并且** 系统必须使用 `calculateCreditsFromCost` 函数进行计算

#### 场景：层级定价配置缺失
- **当** 匹配的层级在 provider 的 `tierPricing` 配置中不存在
- **那么** 系统必须抛出错误
- **并且** 错误信息必须包含缺失的层级值和场景名称

#### 场景：参数值缺失
- **当** 请求参数中缺少层级参数（如 `num_images`）
- **那么** 系统必须抛出错误
- **并且** 错误信息必须说明缺少的参数名称

#### 场景：参数值无效
- **当** 请求参数中的层级参数值不是有效数字
- **那么** 系统必须抛出错误
- **并且** 错误信息必须说明参数值无效

### 需求：场景层级配置

系统必须支持在场景配置中定义层级参数，包括参数名称、层级列表、最小值和最大值。

#### 场景：配置层级参数
- **当** 管理员创建或编辑使用 `tier-based` 计算器的场景
- **那么** 系统必须允许管理员配置层级参数名称（如 `num_images`, `duration`）
- **并且** 系统必须允许管理员配置层级列表（如 [5, 10, 15, 30]）
- **并且** 系统必须允许管理员配置最小值和最大值（可选）

#### 场景：层级参数名称验证
- **当** 管理员保存场景配置
- **那么** 系统必须验证层级参数名称不为空
- **并且** 如果参数名称为空，系统必须显示错误提示

#### 场景：层级列表验证
- **当** 管理员保存场景配置
- **那么** 系统必须验证层级列表至少包含一个值
- **并且** 系统必须验证所有层级值为正数
- **并且** 系统必须验证层级值无重复
- **并且** 如果验证失败，系统必须显示错误提示

#### 场景：添加层级值
- **当** 管理员在层级配置界面添加新的层级值
- **那么** 系统必须将该值添加到层级列表
- **并且** 系统必须自动对层级列表排序
- **并且** 系统必须在界面上显示排序后的层级列表

#### 场景：删除层级值
- **当** 管理员在层级配置界面删除某个层级值
- **那么** 系统必须从层级列表中移除该值
- **并且** 系统必须更新界面显示

#### 场景：层级配置持久化
- **当** 管理员保存场景配置
- **那么** 系统必须将层级配置保存到数据库的场景 `params` 字段
- **并且** 层级配置必须包含 `paramName` 和 `tiers` 字段
- **并且** 如果配置了最小值和最大值，必须一并保存

### 需求：Provider 层级定价配置

系统必须支持在 provider 配置中为每个层级设置独立的定价信息，包括成本价格、利润率和 API 配置。

#### 场景：显示层级定价表格
- **当** 管理员查看使用 `tier-based` 计算器的场景
- **那么** 系统必须显示层级定价表格
- **并且** 表格必须包含所有配置的层级
- **并且** 每个层级必须显示：层级值、成本价格、利润率、售价、积分

#### 场景：编辑层级成本价格
- **当** 管理员在层级定价表格中修改某个层级的成本价格
- **那么** 系统必须更新该层级的成本价格
- **并且** 系统必须自动重新计算售价和积分
- **并且** 系统必须在界面上实时显示更新后的值

#### 场景：编辑层级利润率
- **当** 管理员在层级定价表格中修改某个层级的利润率
- **那么** 系统必须更新该层级的利润率
- **并且** 系统必须自动重新计算售价和积分
- **并且** 系统必须在界面上实时显示更新后的值

#### 场景：使用默认利润率
- **当** 管理员未为某个层级设置利润率
- **那么** 系统必须使用全局默认利润率
- **并且** 系统必须在界面上显示使用的利润率值

#### 场景：配置层级 API 端点（可选）
- **当** 管理员为某个层级配置独立的 API 端点
- **那么** 系统必须保存该层级的 `apiEndpoint` 配置
- **并且** 系统必须支持配置 `requestParams` 和 `responseMapping`
- **并且** 系统必须支持配置 `statusQueryEndpoint`、`statusQueryParams` 和 `statusQueryResponseMapping`

#### 场景：保存层级定价配置
- **当** 管理员保存 provider 配置
- **那么** 系统必须将所有层级的定价配置保存到数据库
- **并且** 配置必须保存在场景的 `tierPricing` 字段
- **并且** `tierPricing` 必须是一个对象，键为层级值，值为定价配置

#### 场景：加载层级定价配置
- **当** 管理员打开 pricing 配置页面
- **那么** 系统必须从数据库加载 `tierPricing` 配置
- **并且** 系统必须在层级定价表格中显示所有层级的配置
- **并且** 如果某个层级缺少配置，系统必须显示默认值或空值

#### 场景：层级定价配置完整性检查
- **当** 管理员保存 provider 配置
- **那么** 系统必须检查所有层级是否都有定价配置
- **并且** 如果某个层级缺少成本价格，系统必须显示警告或错误
- **并且** 系统可以允许保存不完整的配置，但必须在使用时报错

### 需求：前端界面支持

系统必须在 admin pricing 页面提供友好的界面，支持层级配置和层级定价的管理。

#### 场景：选择 tier-based 计算器
- **当** 管理员在添加或编辑场景时选择计算器类型
- **那么** 系统必须在计算器下拉列表中显示 `tier-based` 选项
- **并且** 当选择 `tier-based` 时，系统必须显示层级配置表单

#### 场景：层级配置表单布局
- **当** 管理员选择 `tier-based` 计算器
- **那么** 系统必须显示以下表单字段：
  - 层级参数名称（文本输入框）
  - 层级列表（动态列表，支持添加/删除）
  - 最小值（数字输入框，可选）
  - 最大值（数字输入框，可选）

#### 场景：添加层级值界面
- **当** 管理员在层级配置表单中添加层级值
- **那么** 系统必须提供一个数字输入框和"添加"按钮
- **并且** 点击"添加"按钮后，系统必须将值添加到层级列表
- **并且** 系统必须清空输入框，准备添加下一个值

#### 场景：层级列表显示
- **当** 系统显示层级列表
- **那么** 系统必须按从小到大的顺序显示所有层级值
- **并且** 每个层级值旁边必须有删除按钮
- **并且** 系统必须使用标签或卡片样式显示，便于识别

#### 场景：删除层级值界面
- **当** 管理员点击某个层级值的删除按钮
- **那么** 系统必须从列表中移除该层级值
- **并且** 系统必须更新界面显示

#### 场景：层级定价表格布局
- **当** 系统显示层级定价表格
- **那么** 表格必须包含以下列：
  - 层级值（只读）
  - 成本价格（可编辑）
  - 利润率（可编辑，可选）
  - 售价（自动计算，只读）
  - 积分（自动计算，只读）
  - 操作（展开/收起 API 配置）

#### 场景：表格响应式布局
- **当** 管理员在不同屏幕尺寸下查看层级定价表格
- **那么** 系统必须提供响应式布局
- **并且** 在小屏幕上，系统可以使用卡片布局代替表格

#### 场景：实时计算售价和积分
- **当** 管理员修改成本价格或利润率
- **那么** 系统必须立即重新计算售价和积分
- **并且** 系统必须在界面上实时更新显示
- **并且** 计算必须使用与后端相同的公式

#### 场景：表单验证提示
- **当** 管理员输入无效数据
- **那么** 系统必须在输入框下方显示错误提示
- **并且** 错误提示必须清晰说明问题
- **并且** 保存按钮必须禁用，直到所有错误修复

### 需求：数据持久化

系统必须正确保存和加载层级配置和层级定价配置。

#### 场景：保存场景层级配置
- **当** 管理员保存使用 `tier-based` 计算器的场景
- **那么** 系统必须将层级配置保存到 `credit_costs_config` 表
- **并且** 层级配置必须保存在场景的 `params` 字段中
- **并且** 格式必须为：
  ```json
  {
    "tiers": {
      "paramName": "num_images",
      "tiers": [5, 10, 15, 30],
      "min": 1,
      "max": 30
    }
  }
  ```

#### 场景：保存 provider 层级定价配置
- **当** 管理员保存 provider 配置
- **那么** 系统必须将层级定价配置保存到 `pricing_config` 表
- **并且** 层级定价配置必须保存在场景的 `tierPricing` 字段中
- **并且** 格式必须为：
  ```json
  {
    "tierPricing": {
      "5": { "costPrice": 0.01, "profitMargin": 0.5 },
      "10": { "costPrice": 0.018, "profitMargin": 0.5 },
      "15": { "costPrice": 0.025, "profitMargin": 0.5 },
      "30": { "costPrice": 0.045, "profitMargin": 0.5 }
    }
  }
  ```

#### 场景：加载场景层级配置
- **当** 系统启动或刷新配置缓存
- **那么** 系统必须从数据库加载层级配置
- **并且** 系统必须解析 `params.tiers` 字段
- **并且** 系统必须验证配置格式正确

#### 场景：加载 provider 层级定价配置
- **当** 系统计算积分
- **那么** 系统必须从数据库加载层级定价配置
- **并且** 系统必须解析 `tierPricing` 字段
- **并且** 系统必须验证配置格式正确

#### 场景：配置缓存
- **当** 系统加载配置
- **那么** 系统必须缓存配置以提高性能
- **并且** 缓存必须有过期时间（如 60 秒）
- **并且** 当配置更新时，系统必须清除缓存

### 需求：错误处理

系统必须优雅地处理各种错误情况，并提供清晰的错误信息。

#### 场景：层级配置格式错误
- **当** 系统加载的层级配置格式不正确
- **那么** 系统必须抛出错误
- **并且** 错误信息必须说明配置格式问题
- **并且** 系统必须记录错误日志

#### 场景：层级定价配置缺失
- **当** 系统计算积分时发现匹配的层级没有定价配置
- **那么** 系统必须抛出错误
- **并且** 错误信息必须包含场景名称和缺失的层级值
- **并且** 错误信息必须提示管理员配置该层级的定价

#### 场景：参数值超出范围
- **当** 请求参数值小于配置的最小值或大于配置的最大值
- **那么** 系统可以记录警告日志
- **并且** 系统必须继续按最小或最大层级计费
- **并且** 系统不应阻止请求

#### 场景：数据库保存失败
- **当** 保存配置到数据库失败
- **那么** 系统必须向管理员显示错误提示
- **并且** 系统必须保留管理员的输入，允许重试
- **并且** 系统必须记录错误日志

#### 场景：配置加载失败
- **当** 从数据库加载配置失败
- **那么** 系统必须抛出错误
- **并且** 系统必须记录错误日志
- **并且** 系统可以使用默认配置或拒绝请求
