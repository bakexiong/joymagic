# affiliate-admin 规范

## 目的

定义集成在现有 admin 后台中的分销管理模块、其权限可见性规则，以及首版运营视图的最低交付标准。

## 需求

### 需求：Admin 必须提供内嵌式分销管理模块

系统必须在现有 `admin` 管理后台中提供分销管理模块，并包含数据概览、推广者管理、申请审核、佣金管理、提现管理、全局配置页面。

#### 场景：有权限的管理员访问分销模块

- **当** 用户已拥有 `admin.access` 与 `admin.affiliate.read` 权限
- **那么** 系统必须允许其访问 `/admin/affiliate/*` 页面
- **并且** 页面必须复用现有 admin 布局与导航体系

#### 场景：管理员进入默认分销入口

- **当** 用户访问 `/admin/affiliate`
- **那么** 系统必须跳转到默认概览页
- **并且** 默认概览页必须展示分销关键运营指标

### 需求：分销模块入口必须受权限控制

系统必须同时从导航可见性与页面访问控制两个层面限制分销模块。

#### 场景：用户缺少分销模块权限

- **当** 用户拥有 `admin.access` 但缺少 `admin.affiliate.read`
- **那么** admin sidebar 中不得显示分销管理模块入口
- **并且** 用户直接访问 `/admin/affiliate/*` 时必须被重定向到无权限页面

#### 场景：用户拥有模块级通配权限

- **当** 用户拥有 `admin.affiliate.*` 或 `*`
- **那么** 系统必须视为其拥有分销模块访问权限
- **并且** admin sidebar 必须显示分销管理模块入口

### 需求：分销模块首版必须支持静态运营视图

在后端接口尚未接入时，系统必须使用静态 mock 数据提供稳定可浏览的运营后台页面。

#### 场景：查看推广者、佣金或提现页面

- **当** 页面尚未接入真实接口
- **那么** 系统必须渲染结构完整的 mock 列表数据
- **并且** 页面必须保留搜索、筛选、状态与操作区域，便于后续替换为真实数据源

#### 场景：查看全局配置页面

- **当** 页面尚未接入持久化能力
- **那么** 系统必须展示可编辑的配置表单结构
- **并且** 页面必须清晰呈现佣金、追踪、提现、反作弊和协议设置分区

### 需求：数据库必须提供分销业务主数据模型

系统必须提供分销申请、推广者档案、点击归因、佣金结算、提现申请和全局配置的持久化表结构，并与现有 `user / order / subscription` 建立关联。

#### 场景：推广者申请与审核

- **当** 用户提交成为推广者的申请
- **那么** 系统必须将申请存入 `affiliate_application`
- **并且** 申请记录必须包含申请状态、目标等级、PayPal 账号、社媒信息、渠道说明、审核人、审核时间与驳回原因

#### 场景：审核通过后成为推广者

- **当** 审核通过申请
- **那么** 系统必须在 `affiliate_profile` 中保存唯一推广码、推广者状态、等级、自定义佣金比例和佣金余额快照
- **并且** `affiliate_profile.user_id` 必须与站内用户一一对应

#### 场景：记录点击与归因关系

- **当** 访客通过推广链接访问并最终注册或下单
- **那么** 系统必须在 `affiliate_referral_visit` 中记录点击事件
- **并且** 系统必须在 `affiliate_referral` 中记录推广者与被推广用户的唯一归因关系

#### 场景：生成佣金记录

- **当** 被归因用户产生首单或续订
- **那么** 系统必须在 `affiliate_commission` 中记录佣金来源订单或订阅、佣金类型、比例、金额、可结算时间与结算状态

#### 场景：申请提现

- **当** 推广者申请提现
- **那么** 系统必须在 `affiliate_payout` 中保存提现单号、申请金额、审核状态、打款信息与审核备注
- **并且** 佣金记录必须可通过 `payout_id` 与提现单关联

#### 场景：更新系统级分销规则

- **当** 管理员调整首订比例、续订比例、Cookie 有效期、确认期、最低提现门槛或协议文本
- **那么** 系统必须在 `affiliate_program` 中持久化这些规则
